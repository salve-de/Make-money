# Incoming Data Directory Architecture (`data/incoming/`)

本ディレクトリは、外部収集エージェント・別チャット・スクリプトから提出される生データの受入および分類保管庫である。
ファイルが直下に散乱することを防ぎ、データ種別ごとに厳格にディレクトリを分離して管理する。

---

## ディレクトリ構造と役割

```
data/incoming/
├── chat_sessions/       # 【新規受入】各チャットセッションから提出された新規バッチ（未処理）
├── external_collectors/ # 外部AI・他収集スクリプトが生成した大規模収集バッチ群
├── raw_snapshots/       # 一括収集時の生HTML・スクリーンショット・一次情報スナップショット
├── research_bundles/    # R2連携用・企業別リサーチバンドル中間成果物
├── audit_logs/          # データ整合性・P&L・品質監査レポート類
└── processed/           # 【処理完了】中央台帳へインジェスト済みのアーカイブ保管庫
```

---

## 各ディレクトリの運用ルール

### 1. `chat_sessions/`（各チャット提出窓口）
- **用途**: 新規チャットやAIが収集した100件単位等のバッチJSON（未処理）を配置する場所。
- **命名規則**: `batch_[識別名]_[YYYYMMDD].json`
- **フロー**: インジェストスクリプト（`scripts/pipeline/ingest-chat-sessions.ts` 等）で中央台帳へ取り込まれた後、自動的に `processed/` へアーカイブ移動される。

### 2. `external_collectors/`（外部スクリプト・大規模バッチ）
- **用途**: IndieHackers、eBizFacts、Reddit等から大量収集した外部コレクターの生データ。
- **管理**: ソース別・収集日別に保存され、正規化パイプラインの入力源となる。

### 3. `raw_snapshots/`（生スナップショット原本）
- **用途**: WebページのHTML魚拓、スクレイピング生データ、証跡原本。
- **管理**: R2（`foundation-raw`）へのアップロード元およびローカルキャッシュ。

### 4. `research_bundles/`（中間成果物バンドル）
- **用途**: R2登録や証拠統合用に生成されたバンドルJSON群。

### 5. `audit_logs/`（監査レポート）
- **用途**: P&L整合性監査、URL到達性検証、重複検知などのログ・Markdownレポート。

### 6. `processed/`（処理済みアーカイブ）
- **用途**: 中央台帳（`data/entities-index.json`）および R2 へのインジェストが完了したバッチ。
- **保持理由**: 障害発生時の巻き戻し・差分トレース・再監査用。
