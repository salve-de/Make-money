# MAKEMONEY｜事例納品の受領台帳（非公開・監査待ち）

このブランチは収集AIがR2の非公開納品領域に書いた事例の**追記専用受領書**を保存する。GitHub Actionsは使用しない。main、本番R2、公開目録、公開ポインタを変更しない。

## 自動収集AI

1. 既存事例一覧とこのブランチの `ops/case-intake/receipts/YYYY/MM/DD/` を調べ、名称・公式ドメイン・事業ID・別名で重複を確認する。同一事業の新規調査は新IDではなく既存IDの改版とする。R2の全件列挙が不可能なら「重複なし」と断定しない。
2. 調査と同時に**掲載用の自然な日本語記事・表・図解実データ**を制作する。元調査と出典識別子を各事実・金額・図解へ関連付ける。Plausible Analyticsを編集品質の基準事例とし、型を機械的に押し付けない。
3. `saveMakeMoneyJson` → `readMakeMoneyJson(sha256)` でR2非公開領域への保存と一致を検証する。失敗時には保存済みとは報告しない。
4. 1件ごとにSHAとIDを含む不変の受領JSONをこのブランチへ作成する。R2保存済みでもGitHub受領書が未保存なら「引継ぎ未完了」。上書きで状態を変えない。

## 他のAIの取り込み

1. このブランチの受領JSONを日付順に列挙し、SHAを使ってR2から原本を読み戻す。
2. 既存MAKEMONEYの事例・承認・取り込み履歴も合わせて照会し、`case_id + revision + sha256` を取り込み単位にする。同じ内容は冪等にスキップ。別名やドメインによる同一事業も重複登録しない。
3. 原典、記事、図解、数字と権利を独立検査する。監査済みでない約2,000件以上の旧収集データも自動承認しない。
4. 新記事の `research.json`、`article.json`、SVGを既存の `make-money.case-article.v2` に**検査つきで変換**し、**ローカルの監査UIで全文・図表・出典を表示**する。読者向け文章を事実断片から機械的に組み立て直さない。
5. `R2受領`、`原典・権利監査`、`ローカルUI取り込み`、`オーナー承認`、`公開` を個別に追跡する。受領書を読んだだけでは取り込み済みとしない。
6. 正規取り込みと公開は**停止したまま**。自動で公開しない。Plausible Analyticsのみオーナーの完成基準例であり、既存の`reviewState`が未承認でもそれを勝手に書換えない。

## 台帳の制限

現在のR2ツールはSHA指定の保存・読戻しだけ。R2全件検索、事例名検索、リビジョン予約、取り込み状態の書換え、永続的な単一インポートカーソルはない。上記は**運用規約**であり、これらが実装済みという意味ではない。別AIが変更可能なインポート台帳やUIフィルターを構築・検証するまでは、受領書の日付順列挙とR2読み戻しに基づき未取り込みの可能性を抽出して個別監査する。並列収集での重複競合は完全に防げない。
