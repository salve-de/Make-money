## 4. Stripe/紹介送金/法務への確認事項

**Stripeへ確認**：
1. Makerが日本のPlatformで、Creatorが自分のSaaSを本人名義で販売し、Makerは0～10%のapplication feeを受け取る場合、どのConnected Account/Direct Charge構成・Merchant of Recordとなるか。
2. 2026-09-28版Connect—Platform Terms §3.1、§3.2、§7の適用日（新規契約・既存契約）、MakerがStripeに負う損失責任とその上限。**契約上のリスクに上限のある構成が実際に用意されるか**。
3. Stripe Managed Riskの日本での適用/審査/価格/上限/対象外・停止/切替時責任、CreatorへのKYCと違反商品審査の当事者を明示。
4. Sellerへカード決済手数料をStripeが直接請求する方式とMakerが決済料金を設定する方式、月200円+0.25%+250円の適用、Billing費用、refund/dispute対応、売り手の未払損失の帰属を請求書レベルで確認。
5. 2回目以降のSubscription application fee、Makerと各SaaSのEntitlement、返金/失敗/解約/売主Stripe解除後の処理、本人の顧客情報をMakerに集約しない設計を確認。
6. 第三の紹介者へ報酬を払うための合法な日本円送金の仕組み、外部国送金条件、必要なIdentity、最低額と税務/返金取消を確認。

**日本の専門家へ提出する図**：
- Maker PRO会費：Buyer → Maker → 決済サービス、Makerが情報商品を提供する。
- 独立SaaS：Buyer → Creator本人Stripe等 → Creator本人SaaS役務、Makerは契約に基づくfeeまたは別の紹介対価のみ受領。
- Referrer：Creatorから正式な販売成果の対価を得てReferrerへ適法に支払う方法（Makerが預かり金/送金業者になるのかならないのか）。
- AI Builder：Creator → Makerの利用画面 → 外部Provider、Makerが触れるプロンプト/ID、直接契約か代理/API再販か。
- Credits：無料付与と有償購入を区別し、利用目的/失効/返金/解約/未使用残高の処理を示す。
- UGC/権利：既存事例出典、画像素材、本人の生成作品、著作者、掲載許諾、広告主と記事投稿者の区別。

法務確認項目は特商法、資金決済法、個人情報保護法（外国第三者/委託）、著作権/商標、景品表示法、取引DPF消費者保護法、情報流通関連法制、適用税務。規約案だけでなく**実際のUI/利用者のクリック/本当のデータフロー**と照合してもらう。

## 6. 判定を変える停止条件

- **AI本番NO-GO**：商用組込やMaker側補償の上限が不明、API契約不許諾、入力データの学習等がMakerの説明と不一致、完成物のコードを本人が取れない、追加請求が制御不能。
- **本人公開NO-GO**：Maker名義でだけ本番公開、Makerの解約で停止、DB/Authユーザーが移せず制作者が合理的に独立できない、商用禁止Freeプランへ自動公開。
- **マーケット決済NO-GO**：Connectの想定リスクが上限なし、Makerが顧客の返金/損失を無条件負担、売り手の本人性不明、2回目請求でSaaS権限が一致しない。
- **記事/紹介NO-GO**：Creatorの同意なく非公開情報を公開、虚偽広告を放置、実在しない販売実績表示、紹介者の適法な送金方法が未確定なのに支払い済みと見せる。
- **無料生成NO-GO**：原価と限度額が実測できない、失敗/再試行が無制限、新規利用者の悪用でMakerの支出が無限定に増える。

停止時に「作れないので辞める」「単なる外部リンク集に変える」と即断しない。**代替Provider、契約形態変更、本人直接契約、情報商品の先行検証、正式な紹介者契約のいずれが元の価値と実利益を最も守るか**比較する。
