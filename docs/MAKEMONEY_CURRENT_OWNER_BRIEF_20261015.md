# MAKEMONEY｜2026-10-15の現行方針・収集対象・記事制作・保存と取込み

> **最優先のオーナー指示**：普通に調べて、普通に分かりやすく表示する。ユーザーは『何をどう売り、どう人を集め、どう稼ぎ、なぜ伸びたのか』という成功事例を見たい。『利益ではない』『未確認』『調査記録に残す』『誰でも成功できるわけではない』など、読者にとって不要な言い訳・監査説明・制作者メモを画面に出さない。収集を過剰に厳密化すること自体を目的にしない。ただし売上を利益と偽る、架空の数字を作る、掲載権のない写真を転載することはしない。

この文書は過去の『最終』や旧テンプレより後の、2026-10-15の明示指示を優先して**目的・読者体験・編集方針**を継承するための入口。既存データの上書き、未承認の本番変更、権利・公開ゲートの撤廃を認めるものではない。文書の記録と実装・実証・公開は分ける。

## 1. 何をしたいのか

- **最上位目的**：MAKEMONEY運営者の長期的な実利益の最大化。読者が何度も訪れて価値を感じる情報サービスを作る。記事数や多機能さを成果と誤認しない。
- **読者**：稼ぎ方を探す個人、個人開発者、起業や事業運営に関心がある人。見たいのは実在する商売の具体的な売れ方・儲け方・工夫・規模・初期の顧客獲得。
- **当面の情報軸**：①事例（実在の商売・稼ぎ方）、②世界の検索・購入・発注・困りごとなどの需要・トレンド変化、③多数の成功事例を横断した成功の共通点、④そこから考える稼ぐ機会・アイデア。
- **別の軸を混同しない**：企業の成功談だけを並べても『いま需要が伸びる市場』は測れない。検索増加を売上増加と同義に扱わない。日本の政府マクロ統計だけを世界の需要の代替にしない。
- **長期構想**：本人がサイトやSaaSなどを作り、本人の所有物として公開し、商品を出品・販売・紹介できる市場や実績フィードバックへ広げる案は保持。ただし近時の優先対象は上の情報提供。外部AI/ホスト/Stripe・料金・本人公開・ロイヤリティは、以前『最終』と書かれていても本番採用が決まっていない。収益性・実原価・規約・責任を再検討する。
- **画面**：既存の事例一覧・詳細の暗色配色、情報密度、見出し帯、罫線、文章と図の階層を基本にする。事例記事の改善を理由にUI全体を無断で変更しない。スマホも読みやすくする。

## 2. 事例は何を調べるのか

対象は実在する世界の個人開発、SaaS、Webサービス、アプリ、物販、製造、広告、仲介、サブスク、店舗、ローカル商売、コンテンツ、プラットフォームその他。業種・国・企業規模で恣意的に狭めず、読者が『こうやって売れたのか』と具体的に学べる事例を選ぶ。市場規模が巨大な企業だけに偏らない。

- **商品・事業の実像**：何を誰に提供し、買う人はどう使うか。実製品やサービスの姿、買われた理由。
- **お金が生まれる仕組み**：誰が誰に何の代金を払うのか、料金・課金単位・手数料・売上や販売数・有料顧客数、伸びた実績と時点。
- **始め方と最初の客**：創業者が何を持ち、何を作り、最初の購入や認知をどう作ったか。実際の投稿、営業、紹介、価格、反応。
- **成長の過程**：口コミ、SNS、検索、提携、小売店、広告、製品改善、顧客の継続など、誰が何をしてどう結果が変わったか。
- **事業の運営**：開発、仕入れ、製造、物流、支払い、サポート、人数、外注、技術、設備とその工夫。
- **売れた理由と違い**：顧客が価値を感じた具体的な差、競合との違い、その商売固有の独創的な仕組み。実際に根拠があるときだけ結果との関係を説明。
- **転機**：成功に直接つながった失敗からの改善、事業の変更、重要な転機があれば経緯を示す。
- **周辺の面白い事実**：値上げ、紹介料、商品設計、具体的な検索需要、経営者の工夫、時代の変化など。上の項目にない有用情報も収集する。

これらは調査の候補であって、全件必須の章や空欄埋めではない。事例ごとに重要な内容が異なる。赤字・費用・制約・未確認事項に出会ったら研究原本に残してよいが、**普通の成功紹介では失敗・赤字・リスクを主題にせず、売れた理由・商品・実績・成功の工夫を主役にする**。ただし赤字を黒字と偽るなど事実に反する印象を作らない。

## 3. 他のコンテンツは何を集めるのか

- **需要・トレンド**：日本以外を含む地域別の検索関心、実際の購買・価格、マーケットの販売動向、SNSや掲示板の具体的な不満、求人、広告、発注など、需要の発生・変化を示す観測を探す。Google Trends等は候補。商用での取得・保存・表示・再配信は別条件なので確認し、どれか一つのデータだけで市場全体を断定しない。
- **成功のエッセンス**：蓄積した複数事例から、繰り返し使われる有効な売り方、商品の工夫、集客、分配・運営の仕組みを、実際の例と数字で示す。抽象的な『追い風』『勝ちパターン』だけで終えない。
- **アイデア・機会**：市場の兆候と実在の事例から、ユーザーが自分で取り組む案を考える。事実とAIが新たに提案したものを取り違えない。
- **更新の区別**：最近本当に変化した事柄と、最近発見した古い成功例を混ぜて『今日伸びた市場』と表示しない。

## 4. 文章はどう作るのか

1. 先に**読者がこの事例で何を知りたいか**を考える。事業全体を把握し、『売り方』『初めの客』『拡大の工夫』『成果』など本当に重要な説明を選ぶ。
2. 調査と同時に記事の見出し・自然な日本語の文章を作る。『何が黒字』『誰が買った』『どう広がった』『何の金額か』が文として成立しなければ追加調査する。データの断片を後から機械的につぎはぎしない。
3. 全体を読み物として自然につなぎ、見出しは疑問形の作業メモでなく**答えや実際の特徴**を示す。必要な詳しさは削らず、同じ説明の繰り返しや抽象的な言葉は削る。
4. 数字は普通に正しく書く。例：広告の売上が103万ドルなら『広告枠を販売し、約5か月で売上103万ドルに達した』。そこに『利益ではない』とわざわざ足さない。逆に売上を利益と間違えたり、出典にない初客や金額を作り足したりしない。
5. **読者向け本文に制作者の注記を一切混ぜない**。『出典が足りない』『調査記録に残す』『記事には載せない』『誰でも同じやり方で稼げるわけではない』等は調査・QA欄のみ。値が確認できない任意項目は表示しない。
6. 成功事例は成功の経緯が主役。赤字・失敗・リスク・限界を網羅しない。明確な失敗→改善→成功という転換点など、成功の中身の説明に不可欠なら使う。
7. 不明瞭な文、数値の単位・期間の取り違え、内部メモ混入、見出しの違和感だけは普通の編集として直す。**何重もの厳格な監査自体を記事の目的にしない**。文書チェックやアルゴリズムの合格だけで『読者が理解できる』と証明したことにはしない。

## 5. 図表・画像

図は必要な場合に作る。実際のお金の流れ、顧客が買う手順、商品の仕組み、年表、比較、確認済みの売上推移など、**文章だけより理解しやすいもの**を選ぶ。デザインのためだけに図を量産しない。オリジナルSVGは実際のSVG内容と対応する見出しを保存し、数値・期間を記事と合わせる。他社の製品写真・サービス画面・ロゴなどは元情報と利用条件を確認してから使い、勝手な転載はしない。
