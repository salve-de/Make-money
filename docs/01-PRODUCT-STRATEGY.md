# Product Strategy

## 1. 戦略判断

作るべきものは「ビジネスアイデアを大量生成するサイト」ではない。

**実際に金が動いた証拠を起点に、次のOpportunity Windowを見つけ、既存サービス・需要者・製作者を接続するDB** を作る。

## 2. 表側・裏側・収益商品の分離

| 層 | 役割 | 主な価値 |
|---|---|---|
| 表側 | Opportunity Feed | 驚き、夢、発見、継続訪問 |
| 裏側 | Money Flow Database | 根拠、検索、比較、履歴、関係性 |
| 行動層 | Product / Demand / Intent | 掲載、ベータ募集、問い合わせ、送客 |
| 有料層 | Research / Watch / Analytics | 監視、詳細比較、通知、分析、法人利用 |

## 3. 中核オブジェクト

- **Money Signal**：売上、利益、契約、支出、調達、売却、価格変化など、金が動いたイベント
- **Demand**：欲しい、困っている、既存製品が足りない、支払意思があるという需要
- **Opportunity**：Money Signal、Demand、競争、タイミングから導いた参入余地
- **Product / Service**：実在する商品・アプリ・サイト・事業
- **Entity**：人物、企業、政府、投資家、組織
- **Evidence**：一次資料、本人開示、第三者推定、未確認情報
- **Intent**：顧客、ベータ利用者、提携、採用、投資、売却など、掲載者が今求めているもの

## 4. 優先ユーザー

### Phase 1

1. 儲かる事業を眺めたい人
2. 次に作るものを探す個人開発者・起業準備層
3. 自分のサービスを掲載したい運営者
4. 新しいサービスを探す買い手・利用者

### Phase 2

5. 情報発掘者・キュレーター
6. 代理店・フリーランス・専門家
7. 投資家・小規模事業買収者
8. 新規事業担当・コンサル・市場調査担当
9. 発信者・ニュースレター・アフィリエイター

## 5. 最初の市場範囲

広い構想を維持しつつ、初期データはInternet-native small businessesへ集中する。

- Micro SaaS
- Web／モバイルアプリ
- Browser extensions
- Shopify apps
- WordPress plugins
- Small developer tools
- ニッチDB／ディレクトリ
- デジタル商品
- 有料ニュースレター／コミュニティ
- 小規模Web事業の売買

政府・大企業の支出は、個人・小規模事業者が取れる周辺機会へ翻訳できる場合に強く扱う。

## 6. 参入方法の共通分類

Opportunityは、次のいずれかへ構造化する。

1. 別地域・別言語へ移植
2. 特定業界向けに垂直化
3. 既存製品の不足機能を補完
4. 売れている事業者へ道具を売る
5. 手作業サービスから開始し、後でソフトウェア化
6. 小規模事業を買収し改善
7. 参入せず、危険市場として回避

## 7. やらないこと

- AIが生成した根拠のないアイデアを大量に並べる
- 自由投稿を無審査でメインフィードへ流す
- 資金調達額を売上のように見せる
- スポンサーがOrganicランキングを購入できるようにする
- 初回から重い質問フォームを要求する
- 掲示板、求人、M&A、投資、決済を同時に完成させる
- すべての国・業界を初期から同じ深度で扱う

## 8. 事業仮説

無料ユーザーは、成功金額、意外な事業、無名からの成功、まだ間に合う感覚のために来る。有料ユーザーは、根拠、監視、比較、時間短縮、他人より早い発見へ支払う。掲載者は、顧客、ベータ利用者、被リンク、需要分析、リード獲得へ支払う。
