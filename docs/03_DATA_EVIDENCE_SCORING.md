# データ・根拠・スコア設計

## 1. 数字の型

金額は最低限、次を分ける。

- revenue — 顧客売上
- profit — 利益
- MRR / ARR — 月次・年次継続売上
- GMV — 取引総額
- funding — 資金調達
- acquisition — 事業売買
- contract — 契約額
- ceiling — 契約上限額
- ad_spend — 広告支出
- market_spend — 市場支出
- switching_spend — 乗換支出
- data_revenue — データ販売売上
- estimate — 外部推定

各金額に必要な属性：

- amount
- currency
- amount_label
- period_start / period_end または signal_date
- payer
- receiver
- source_type（分かる場合）
- source_url（分かる場合）
- observed / estimated / reported / unknown
- verification_status（SUPPORTED / CONFLICTED / UNVERIFIED 等）
- collected_at

## 1.1 出典なしの候補

出典は収集・保存・表示の必須条件ではない。出典がない金額や事例は `UNVERIFIED` と「出典未取得」を付けて保持し、検証済みの数字・推薦根拠・成功保証としては扱わない。後から出典が得られた場合は、元の観測を消さずに追補する。

利益は最優先の金額群とし、売上、粗利益、営業利益、純利益、利益率、コスト、個人手取りを別の金額種別・期間で保持する。利益が分からない場合は推測で埋めず、不明とする。

## 2. 根拠ランク

### A — 一次根拠

公的API、法定開示、確定成約、公式調達、署名済み契約、監査資料など。

### B — 直接開示

運営者・企業の直接開示に、料金、利用者推移、複数資料などの裏付けがある。

### C — 推定

信頼できる第三者推定、サンプルの限定された調査、間接指標。

### D — 未確認

自己申告、単独投稿、裏付けのない噂。発見用には残すが、確認済みと混ぜない。

## 3. Opportunity Score

現実装の重み：

| 要素 | 重み | 意味 |
|---|---:|---|
| Momentum | 28% | 新規支出、成長、変化速度 |
| Gap | 27% | 需要に対する既存解決策の不足 |
| Buildability | 20% | 個人・小規模チームの実装・販売可能性 |
| Evidence | 17% | 根拠の直接性と信頼度 |
| Freshness | 8% | データの新しさ |

根拠換算は A=100、B=80、C=58、D=32。鮮度は日数に応じて減衰し、最低30を維持する。

総合点だけを見せず、各要素を必ず並べる。点数は事実ではなく比較補助である。

## 4. Demand Gap Score

| 要素 | 重み |
|---|---:|
| 「欲しい」票 | 30% |
| 「払ってもよい」票 | 27% |
| Pain score | 28% |
| 既存サービスの少なさ | 15% |

「欲しい」だけでは娯楽的反応が混ざるため、支払意思と代替行動を別に保持する。

## 5. Opportunity判定

- **Observe** — 興味深いが証拠または継続性が不足
- **Validate** — 顧客確認を始める価値がある
- **Enter** — 根拠、需要、入口が揃う
- **Avoid** — 競争、規制、取得コストなどが期待値を上回る

判定理由を短文で保持し、スコアだけで自動断定しない。

## 6. 出典履歴

同じ主張へ複数ソースを紐付ける。更新時に上書きせず、次を記録する。

- 取得日時
- 公開日時
- URL
- 発行者
- 何を立証するか
- 抜粋ではなく要約
- 根拠ランク
- 前回値
- 訂正理由
- 検証者

## 7. データ取得の優先順位

1. 公的・公式API
2. 法定開示・企業IR
3. 公式料金・導入事例・売却発表
4. 運営者による接続指標
5. 信頼できる第三者推定
6. ユーザー投稿

有料DBの画面を無断で再配布しない。API・データライセンス、利用規約、再利用条件を取得源ごとに記録する。

## 8. 品質チェック

- 売上、GMV、資金調達、利益を取り違えていないか
- 粗利益、営業利益、純利益、手取りを取り違えていないか
- 累計と単月を取り違えていないか
- 契約上限と実支出を取り違えていないか
- 通貨換算日があるか
- 推定モデルと観測範囲があるか
- 成功例だけでなく撤退・減少も記録したか
- 同じ企業・サービスの重複を統合したか
- 出典URLが主張を本当に支えるか
