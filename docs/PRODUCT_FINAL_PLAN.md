## 2. 今回採用した事業構造

第一目的は、MAKEMONEYの運営者が大きく、長期にわたり利益を得ること。

- **事例**：一覧・検索・個別記事を無料で公開し、関心と信頼を集める。
- **機会**：「新しい商売機会」と「稼ぎ方の型」の完成済み調査ライブラリ・更新をPROの主力商品にする。
- **作る**：本人の企画・調査／制作／販売を、一つの事業プロジェクトに保持する。PRO未加入でも初回無料枠と追加購入で実際に制作できる。
- **市場**：出品・紹介参加は無料。実際に成立した取引から手数料を得る。外部商品、利用者の記事、紹介、広告も接続する。

主要入口は4つであり、画面が全部で4枚という意味ではない。事例を読まずに制作してよく、商品を外部から持ち込んでもよい。紹介者に制作やPRO加入を強制しない。

## 3. 旧案から変わった部分

旧「事例・傾向・事業検討・作る・市場」の5分類を、対象と利用目的に基づく4入口へ再編する設計を採用する。

特に、前段の4入口案で曖昧だった点も今回の最終要件で確定している。共通の調査情報は「機会」、本人専用の事業検討は「作る」内のプロジェクトへ置く。単に傾向と事業検討の画面を一枚につなぐだけではない。

個別AI相談だけを有料商品の中心にせず、まだ起業する予定のない人も読む価値を得られる情報商品を持つ。共通レポートの閲覧と、外部原価がかかる個別AI処理の利用枠を分ける。

開始価格・枠は最終要件7章、採算の前提は8章とJSONを参照する。先行する文書の「料金未決定」や無料制作の回数案と食い違う場合は、この最終要件の値を設計上の採用値とする。唯一の最適価格を実証したという意味ではない。

## 4. そのまま守る部分

現在オーナーが評価している事例画面、画像ギャラリー、本文、配色・文字階層、年表等を、再編のついでに全面変更しない。旧5タブとの衝突は明示した設計変更であり、他の承認済みUIの変更許可へ拡大しない。

事例から機会、本人の企画・制作・販売、実績の還元へつなぐ構想は維持する。M&A、独立した比較プロダクト、巨大SNSを中核に追加しない。既存の事実・権利・保存の管理、他の作業者の変更、既存購入者の権利を保護する。

## 5. 実装と本番反映の境界

今回の保存で、新4入口・価格・無料枠・課金機能が本番で動いたとは扱わない。文書保存は、デプロイ、実課金、外部契約、本番データ変更を実行する包括許可ではない。

実装依頼を受けた担当は最終要件のR1〜R4を実装単位へ落とす。接続不能、契約不適合、実原価超過などの具体的な阻害要因がある場合だけ、その部分の代替を示す。事業戦略全体を再び他のAIへ白紙委任しない。

実装は、情報設計 → 実装 → 実データ → 実画面で評価 → 再修正。受入条件、残高・権限・返金・公開の試験を満たすこと。事例1,000件の自動追加は並行し、その完了まで有料価値の検証を先送りしない。
