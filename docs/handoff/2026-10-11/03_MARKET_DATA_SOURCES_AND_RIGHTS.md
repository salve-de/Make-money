# 03｜世界の需要データ・継続収集・AI分類・商用利用

対象：単なる日本のマクロ統計ではなく、**世界中で具体的に何が検索され、購入され、話題・不満になり、どこへ予算が流れるか**を継続収集し、最近の需要・稼ぎ方の情報として表示するための設計。

## 0. 問題の定義

- オーナーは「Google Trendsとかないのか」「政府統計だけ／日本だけは弱い」「それは需要じゃない」と再三訂正した。
- **特定の企業事例を集める経路とは別に、検索／購買・取引／不満や発注／広告／求人／商品と競争環境の変化の多面的な経路を作る**。
- ある検索キーワードの増加率だけでは、検索基数・購買転換・代替供給・事業者利益は分からない。最初から複数の強さの異なるシグナルを設計する。
- 国家全体の家計支出、消費者物価、観光客数、企業数は市場背景や需要の周辺情報。**MAKEMONEYが本当に表示したい「いま欲しがる商品、直面している面倒、支払いの兆候」の代替にはならない。**
- 既存事例（成功談）は商売の仕組みと実行条件の参考資料。直近の市場関心や成長率の根拠に格上げしない。

## 1. 主力候補：需要に近いシグナルを段階ごとに扱う

| シグナル | 具体的に分かること | 限界・誤解しやすい点 | 取得候補 | 期待頻度 |
|---|---|---|---|---|
| **検索関心／急上昇** | 商品名・課題・実行方法について、何を調べ始めたか | 検索数の分母が小さい上振れ、季節性、SNSによる瞬間的な話題、売上との違い | Google Trends、Google Adsキーワード統計、DataForSEO、Yahoo! DS.INSIGHT等 | 日次〜週次（ソース依存） |
| **マーケットプレイスの検索・販売** | 特定の品目・カテゴリ・商品が探され、場合によっては買われた | 平台内の販売であり全市場ではない。検索と販売は別。個々の店舗の実データは取得制限あり | Etsy Seller Trend Report、正式な小売データ提携、許諾された販売ランキング等 | 週〜月 |
| **顧客の不満・相談・レビュー** | 既存商品のどこが使いにくいか、何のために代替を探すか | 投稿数は母集団や支払額を表さない。同じ投稿の転載・ボット・広告を含み得る | Redditの正式契約、Stack Exchange等ライセンス対応API、レビュー事業者との契約 | 日次〜週次 |
| **発注・入札・予算支出** | 企業・政府がどんな機能や業務に予算を付けているか | 発注条件・実契約額と応募数は別 | SAM.gov、EU TED調達データ、合法な民間案件データ | 日次〜月次 |
| **求人と業務上の不足** | 職種、技能、ツール、作業負担に投資し始めた兆候 | 求人は支払需要と同義でなく、募集が充足するか不明 | 求人サービスの正式API・提携、求人元公式発表、集計許可データ | 日次〜月次 |
| **広告・購買意欲に近い指標** | 広告主が入札する語、競争度、広告単価、商品流通に関する情報 | 高CPC＝参入者の高利益ではない。契約上の外部再配信制限 | Google Ads API/Keyword Planner、正規SEOデータプロバイダー、広告ライブラリ | 週次〜月次 |
| **価格・商品・競合の変化** | 正式販売価格・課金方式・機能・サービス停止の変化 | 新機能の発表は需要の増加ではない | 事業者公式料金／リリースノート／API、正式な価格監視契約 | 日次〜週次 |
| **公的統計・経済・人口** | 規模、国・地域、支出背景、長期変化 | どんな具体的商品を今欲しいかを直接示さない場合が多い | e-Stat、Eurostat、World Bank、米国Census、JNTO等 | 月次〜年次 |
| **実在事業の収益／継続／失敗** | どんな形の事業が成立・失敗したか、原価や初期条件 | 生存者バイアス。過去の成功は最近の需要の証明ではない | MAKEMONEY既存事例、公式決算、検証済み収益サービス等 | 事例公開ごと |

強い需要の候補を選ぶ条件として、**検索／具体的な困りごと／実際の購買・発注**が重なる場合に優先度を上げる。ただし需要の「確率」を機械的な点数から出さない。

## 2. Google Trends と広告系API（重点）

### 2-1. Google Trends（公式）
- 「急上昇中」「調べる（Explore）」を対象とする。検索関心は正規化された相対指標・特定期間の急上昇であり、売上・絶対人数ではない。
- Trending now は公式サイトで多数の地域に対応し、CSV/RSS等の提供がある時点もある。ただし**HTMLを大量スクレイピングして商用再配信する契約権利を得た意味ではない**。公式利用条件・技術提供状態を継続確認。
- 公式Google Trends APIは、2025〜2026の公開資料に**アルファ・限定アクセス**との記載がある。通常のGoogle Cloud API同様に誰でもフル利用可能と誤認しない。
- API認証、リクエスト上限、参照国、保存・商用表示・再配信を正式に確認。正式な使用権利がない場合は、**公式サイトへのリンク＋自社が独立に根拠を確認した事実の解説**など利用可能な範囲に限定。
- 日次収集候補：急上昇テーマのID/キーワード、地域、観測時刻、カテゴリ、期間、成長方向、関連キーワード。スパイクを周期的な需要と誤読しない。

### 2-2. Google Ads Keyword Planner／Google Ads API
- キーワード案、検索量の歴史的指標、地域、広告の競合や予測等を扱うAPIがある。
- 実際のアクセスには承認済み開発者トークン・アカウント・条件が必要。**Google Adsの指標を競合サイトの有料DBへそのまま転載できるかは別途規約審査**。
- 具体的な検索需要の程度・購買意向の補助となるが、競争スコア・CPCを収益性スコアにしない。

### 2-3. 正規有料データ会社
- DataForSEO：検索・トレンド／キーワード／SERP／Shopping関連API等が候補。少額API単価の表示は**自社のユーザー向け再配信許可や総月額の保証ではない**。保存期間、生成した独自分析の公開、原データ再配信、ブランド出典表示、APIキーと利用規約、国別課金を確認。
- Semrush Trends／Traffic Analytics／データ製品：業界・サイト流入・SEO動向等の候補。通常のユーザー契約とAPI契約・第三者配布の条項を区別。料金・上限・対象国・再配信を見積もる。
- Similarwebの市場インテリジェンスも候補。自社所有データでなく、推定トラフィックの利用範囲・別商品への再販が許されるかを確認。
- 低費用でも外部原データを100%再掲して有料販売する設計は危険。**許された指標を適切に加工・統合する価値**と権利は別に設計する。

## 3. 世界の具体的な商品・人間の需要

### 3-1. Pinterest
- Pinterestの公式2026トレンド・趣味レポートに、手芸・古着の修繕・自宅カフェ・占星術・手紙・香り・旅行等に関連する検索増加の記載がある。
- **公表資料からの事実**：プラットフォーム上の特定キーワードの変化。国・対象者・比較期間・対象数が明示されている範囲で使う。
- **未証明**：当該商品の売上総額、需要増加の絶対人数、日本市場の動き、後発の利益。
- 自動収集：一般公開記事を無許可で全文再配信する設計は採用しない。公式API・提携・公開記事の事実への適法な引用などを権利別に検討。

### 3-2. Etsy
- Etsy Seller Trend Reportの公開事例には米国利用者のcrochet clothing（販売動向）、handmade/wedding/journal等の検索増がある。
- **検索上昇率と「販売が何％増えた」を混ぜない**。レポートの国、比較期間、対象はEtsy内の限定的なデータであり全世界の消費動向と読み替えない。
- Etsyの出店者向けAPIと、市場全体の詳細な売上データ取得権は異なる。日次の商品ランキングや売上を無制限にコピーできると決めつけない。

### 3-3. Stack Overflow等の利用者調査
- Stack Overflow Developer Survey 2026等の調査は、AIツールの利用・切り替え理由・仕事の課題を知るのに向く。
- 回答者の利用割合は、全世界人口・全企業・すべての開発者の利用率や前年比成長率ではない。設問ごとに分母も変わる。
- 調査ローデータのODbL 1.0等のライセンスや派生DB条件、引用条件を精査する。定期アンケートの情報を毎日更新に変装しない。
- Stack Exchange本文・Redditやレビューはライセンス／API約款が別。引用数・データ保存・配布先・商用用途を確認。

### 3-4. TikTok・YouTube・SNS・レビュー
- TikTokのCreative Center、YouTube Trends、広告ライブラリ、SNS検索、Reddit、G2/Trustpilot等は**トレンドや不満の発見候補**。
- 公式の公開ダッシュボードの存在は自動収集・商用再販売権ではない。特にRedditの商用データ利用には別許諾が必要となる場合がある。
- SNS上で何度も同じ悩みが話題になっていても、支払う顧客数や市場規模とは異なる。
- 口コミや個人の発言は個人情報・名誉・文脈を守り、一般利用者向けに無差別全文転載しない。

### 3-5. 公共調達・事業者の仕事の予算
- 米国SAM.govのAPI・米国Census、EUのTenders Electronic Daily（TED）オープンデータ、国別の公開入札情報が候補。
- 何の仕事に予算が付き、案件が増えているかを調べる。ただし予定発注・入札公告・落札・実支出を区別。国別のデータ再利用条件とアクセスキーを確認。
- 民間のUpwork/求人/制作依頼等は独立のAPI・契約が必要。公開求人・案件ページを無断大量クローリングして再配信する設計は避ける。

### 3-6. 公的マクロ統計の役割
- 日本のe-Stat APIは、所定の表示・出典条件を守った商用再利用が公表されている。家計消費状況調査のネット通販利用、商業動態統計、雇用、物価、企業統計などが補助になる。
- Eurostat、World Bank、米国Census、JNTO等には世界・国別データがある。**国ごとに観測範囲と更新日が違う**ので単純なランキングは禁物。
- JNTOの観光人数と観光消費額は別指標。EC利用者割合とEC売上や商品の人気も別。
- オーナーの最新訂正に従い、日本の政府統計だけを「需要」としてトップに並べない。

## 4. 権利と商用利用の3段階（設計上の整理）

**入力として見る権利、内部で処理する権利、MAKEMONEYの公開ページで商用再掲する権利は同じではない。**

| 状態 | 収集・利用の扱い |
|---|---|
| **APPROVED_PUBLIC** | 該当するデータセット／APIの契約・商用掲載範囲を読み、根拠（規約URL・バージョン・利用者・保存/再配信制限・帰属）を記録して合格 |
| **INTERNAL_ONLY_OR_LIMITED** | 閲覧可能でも公開数値の大量転載や再配信許可が不明。公開へ進めない。適法な短い引用や独自の事実説明の可否も別途確認 |
| **BLOCKED_OR_UNKNOWN** | 契約上禁止、権利不明、抽出不能、閲覧条件違反、個人情報リスクなど。表示への自動昇格禁止 |

- 権利ゲートは既存のMake-Money/Universal Foundation正本と整合させる。**この表で本番の3層の正式名称や許可範囲を上書きしない**。
- データ提供企業へ確認する要件：①日本居住の運営者のAPI利用可否 ②商用SaaS内のエンドユーザー表示可否 ③有料会員への再配信・派生指標の販売可否 ④クエリ・データ保存期間 ⑤ダウンロードやAPIとしての再提供 ⑥出典/ロゴ ⑦国別カバレッジ ⑧レート・再販契約 ⑨自動更新 ⑩停止後の表示義務 ⑪賠償・補償 ⑫価格・従量コスト。
- **公開記事の短い事実の解説／統計の引用と、データベースの定期的な全量再配信は異なる**。契約審査が完了するまで後者を前提にしない。
- 出典の画像・企業ロゴ・スクリーンショットの転載は、商品数値とは別に権利評価する。既存の媒体権利ゲートを緩めない。

## 5. AIによる分類と「需要の発見」

AIに全部を自由判断させるのではなく、**複数段階で資料と結びつける**。

1. 取得：正式な取得経路、raw source URL・ライセンス・公開日・観測対象期間・取得時刻を保持。未契約データの閲覧と自動取得を区別。
2. 正規化：国・言語・カテゴリー・商品名・検索語・単位・比較期間・データの分母を揃える。百分率、ポイント差、絶対数、指数100を混同しない。
3. 多言語テーマ解決：「sashiko ideas」→「刺し子」「古着修繕」など。同義語を統合しつつ国別・文化的な意味差は残す。
4. AI分類：安定した大分類＋複数タグ、顧客層、購入目的、商品種別、料金方式、証拠種別、成功のエッセンスとの関連を候補として抽出。根拠がない推論は **HYPOTHESIS** として別フィールド。
5. 差分検出：同テーマの前回と今回で、観測期間・同じ指標・同じ母数が比較できる場合だけ、プログラムで増減を計算する。比較不能なら「比較不能」と記録。
6. 複数資料での確認：検索上昇＋同商品販売の上昇＋顧客の不満／広告投資といった相互補強を確認。同じ元記事の転載を独立ソースと数えない。
7. 新規性と重要性：単純なバズより、買う理由、商売の応用可能性、収益性を評価。ただしオーナーに「強い上振れを見せたい」ためだけに架空スコアを表示しない。
8. 重複・権利・品質・個人情報ゲート：根拠不明、権利不明、数字の意味が違う資料は公開不可。AIの自然言語は事実と予測を分離。
9. 公開：最初の画面は最新の確認済み需要や商品・販売の動き。元企業や出典は要求時の詳細で示す。公開後も最新情報を再検証。

分類精度のE2Eを評価するため、少なくとも日本語・英語・複数分類・曖昧語・同名製品・国境を跨ぐ検索語・異なる観測対象について**人間が正解を付けたテスト集合**を作る。モデル単価の安さだけで選定しない。

## 6. データレコード（推奨フィールド、まだ正式スキーマではない）

- signal_id、theme_id、canonical_topic、raw_keyword、aliases、language、country、geo_granularity
- primary_category、secondary_categories、customer_group、customer_goal、demand_kind、product_forms、price_mechanisms
- signal_type（SEARCH_INTEREST / PURCHASE / SALES / CUSTOMER_COMPLAINT / JOB / CONTRACT / AD / PRICE / PRODUCT_RELEASE / MACRO / CASE_DISCOVERY）
- source_id、source_url、publisher、source_terms_url、license_status、commercial_display_scope、rights_reviewed_at
- published_at、observed_period_start/end、observed_at、collected_at、discovered_at、last_verified_at
- metric_name、metric_value、metric_unit、metric_denominator、base_period、comparison_period、methodology、geographical_scope
- extracted_facts（出典と引用位置）、analysis（根拠付き解釈）、hypothesis（未検証の商売案）、limitations、counterevidence
- source_independence_group、dedup_key、entity_link_refs、related_pattern_ids、related_case_ids
- editorial_quality_state、rights_gate_state、publication_state、source_freshness、superseded_by、correction_log

**日時は4種以上に分ける**：公表日（記事が出た日）／観測対象期間（統計が測った日）／発見日（AIが見つけた日）／取得日時（実際に保存した日）。この区別が曖昧だと偽の最新ニュースになる。

## 7. 初期の継続運用（提案、未承認）

| 処理 | 提案の更新頻度 | 条件 |
|---|---|---|
| 正式に利用許可された急上昇検索／新商品 | 日次〜週数回 | 利用許諾・レート・API費用が合格してから |
| 検索量／購買・発注動向の検証 | 週次 | 母数・比較期間・地域・独立ソースの整合 |
| 事例の新規分析・成功エッセンス | 新規事例追加時＋週次再評価 | 既存の収集仕様・権利・品質ゲートを保持 |
| 公的統計・年次サーベイ | 発表カレンダーに合わせて月〜年 | 数字が変わった時だけ実際の更新として表示 |
| 監視ユーザー向け差分 | 新規に公開可能な変化が確認されたとき | 未読・保存・通知のUXは別途評価 |

これらは**既存の定期収集タスクを勝手に変更する許可ではない**。新しいデータソース／収集タスクを開く前に、既存の通常公開経路・商用権利・重複・費用・公開中止条件と整合させる。

## 8. 利益と費用・依存関係

- 最初から多数の有料APIに契約しない。APIデータ取得＋LLM抽出＋品質検証＋保存＋権利管理＋更新追跡＋閲覧までの1件あたり原価を測る。
- 無料の政府統計だけでは差別化が不足するため、費用が合えば**合法的に表示可能な検索・購買・課題データ**へ投資する。
- 単一のGoogle/Pinterest/Etsyに依存しない。いずれかの提供が止まれば他ソースへの切替／該当項目の更新停止を表示。
- 公開されている売上の大成功例と、今後の参入者の獲得利益は別。広告のCPCが高いことも売上・利益を保証しない。
- ユーザーの価値は「資料の転載」ではなく、**需要を認識する→理由と対価を理解する→実在する商品・成功エッセンスに接続する→市場の変化を追う**という新しい情報構造にある。

## 9. 権利・アクセスの最新判定一覧（2026-10-11時点の調査上の状態）

| ソース | 現時点の安全な扱い | 導入前に必要な確認 |
|---|---|---|
| e-Stat API | 公式の公的統計・出典表示を守る範囲で商用利用可能な素材 | 個別統計とAPIの条件、表示方法 |
| Eurostat／World Bank／米国Census | 公式のデータ再利用条件を満たした範囲で検討可 | データセットごとの例外・表示/ライセンス |
| Google Trends UI | 分析・探索候補。限定APIと画面の公開は別 | 商用API取得、保存、派生表示、再配信の明文 |
| Google Ads API | developer token等の制約下の広告データ | 自社に表示できる項目、第三者再配信とユーザー権限 |
