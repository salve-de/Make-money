# MAKEMONEY｜定期収集AIへのバッチ納品指示

これは自動化タスクのプロンプトに使う**設計用文章**。ここに保存しただけでは定期タスクは作られない。

```
MAKEMONEY向けに、未収集の実在事例を指定件数調査する。
最初に salve-de/Make-money の最新の docs/OWNER_INTENT.md、
docs/CASE_COLLECTION_EDITORIAL_STANDARD.md、docs/CASE_COLLECTION_AGENT_RUNBOOK.md、
docs/CASE_BATCH_DELIVERY.md と未マージの実装PRを確認する。

候補を発見したら既存事例・予約リスト・前回納品のstable entityIdと照合し、
同じ事業を重複調査しない。業態はSaaSに偏らず、物販・仲介・広告・店舗・
サービス・プラットフォーム・失敗例なども含める。

十分な一次情報と合法な出典を集め、出典・時点付き research.json を制作。
事業全体を理解した後で、見出しと重要度、章への割付、重複排除を決める。
各記事を自然な日本語で短く具体的に書く。8章の機械的穴埋めをしない。
根拠がない原価・利益・売上・因果は作らない。
読者の理解に役立つ図は元の事実からオリジナルで制作する。
図の見出しは問いではなく、図から直接分かる情報を書く。
新規事例の文章と図を独立してレビューし、不十分なら調べ直す。

1事例ごとに research.json、article.json、必要なSVG、品質・権利・未確認メモを作る。
バッチのmanifest.jsonに sha256 と新規IDを入れ、
make-money.case-batch.v1 のフォルダまたはZIPで納品する。
資料が取得できなければ捏造せず不足と理由を伝える。
R2書込・GitHub Actions・本番公開・定期設定変更はしない。
納品後、件数・品質・出典と次の取り込み手順を報告する。
```

**重要**：初回の作業では実際のリポジトリと現在のarticle schemaを読む。バッチが形式上通っただけで高品質だとは報告しない。品質が不足した候補は納品しても完成件数に含めない。
