# 他プロジェクトへ適用する最小セット

このファイルは導入用テンプレートです。他のrepoを変更済みとは意味しません。各repoの既存構成を確認してから適用します。

1. `AGENTS.md`冒頭から、そのrepoの`docs/architecture/STORAGE.md`へリンクする。
2. STORAGE.mdの表に実データを当てはめる。project ID、開発・検証・本番のリソース名、認証issuer、schemaとmigrationの場所、担当API、保持期間を記載する。未設定は未設定と書く。
3. 接続設定はホストの構成ファイル一箇所へ集約する。秘密はsecret管理へ置く。別環境への暗黙fallbackは入れない。
4. ユーザーIDをリクエスト本文から信じない。サーバー認証から取り、DB照会も更新も所有者で限定する。
5. 外部JSONを入口で検証する。決済・権利は署名検証と重複排除を行い、ブラウザのフラグを信用しない。
6. 依存制約・型・ユニット・主要導線E2E・本番buildをCIで実行し、mainのrequired checksへ登録する。
7. バックアップを別世代へ保存し、空の隔離環境への復元とアプリ読み戻しを試す。証拠をrepoに記録する。

最初から巨大な共通フレームワークは作りません。再利用はこの契約とテスト観点から始め、同じ接続コードの実利用が複数できたときだけversion付きライブラリを検討します。

## 各データの記載テンプレート

```text
データ名:
所有プロジェクト / 環境:
正本のリソース / tableまたはprefix:
書き込み元API / 所有者の検証方法:
読み取り元 / 公開可能な項目:
schema / migration / schema version:
一意性 / 再実行 / 同時更新 / 途中失敗時の回復:
個人情報 / 保持期間 / 削除方法:
バックアップ / 復元手順 / 許容損失時間 / 許容復旧時間:
選択理由 / 採用しなかった代案:
テスト / 最後に実環境で読み戻した証拠:
```
