# オーナーの意図（何を・なぜ・どこまで）— 最初に読む1枚

最終更新: 2026-09-30。この文書は、オーナー（ユーザー）が会話で繰り返し伝えてきた「何を作りたいか・何を重視するか・何を嫌うか」を1か所にまとめたもの。オーナーは長い指示を書かないので、AI・作業者はここを読んでから動く。
細部の正本: 収集の鉄則と事故録は [`DATA_COLLECTION_MASTER_GUIDE.md`](./DATA_COLLECTION_MASTER_GUIDE.md)、項目の型は [`GOLDEN_INGEST_SCHEMA.md`](./GOLDEN_INGEST_SCHEMA.md)、画像は [`MEDIA_ASSETS_AND_PROVENANCE.md`](./MEDIA_ASSETS_AND_PROVENANCE.md)、保存は [`COLLECT_AND_STORE.md`](./COLLECT_AND_STORE.md)。食い違ったら、この文書の「オーナーの決定」が新しい。

## 1. 何を作るのか（なぜ）
- 読者が「これを見ずに動くのは損だ（自殺行為だ）」と思って金を払う、**資本主義の裏帳簿**。誰が・誰から・何の恐怖や面倒を消して・どれだけ楽に・いくら抜いているか、を1画面で掴ませる。
- 読者が欲しいのは会計の正確さではない。**金の抜き方の構造と規模感と、1秒で刺さる強い一行**。
- 空欄だらけ（「未確認」だらけ）の画面は、正確でも商品として負け。

## 2. 何を集めるか（全項目と、なぜ要るか）
全事例で全項目を埋める。事実が取れない項目は推論で埋める（3章）。

| 項目 | なぜ要るか |
|---|---|
| 強い一行（HEADLINE） | 読者が1秒で「これは本物だ、読みたい」と思う入口。例「工場のラインが止まる恐怖を消して5億（キーエンス）」「構築10日、あとは週1時間の保守。面倒な管理は絶対にしない男の戦略」「パンツ一丁でモニター5枚の前に座る1人が年$20万（Pinboard の絵）」 |
| 社名・何の事業か・創業者・国・URL・創業年・いま営業中か | 身元。本物の会社だと信じてもらう土台 |
| 売上（1点でも。推移が取れれば最高） | 規模感。推移は「伸びた・縮んだ」の物語になり最も強い |
| 費用・利益・利益率・創業者の手残り | 「年商」の見栄を剥いで、実際に手元にいくら残るか |
| 料金と料金の変遷 | 何にいくら払わせているか |
| 客は誰か・客の痛み（即決する恐怖・面倒・恥） | なぜ金を払うのか |
| 最初の客の集め方・伸びた転機・いまの集客 | 読者が一番盗みたい部分 |
| 人数・働き方・外注・自動化・初期資金 | 自分にもできるかの判断材料 |
| 使っている道具・技術 | 真似するための部品 |
| 競合・大手が手を出せない理由 | なぜ小さい者が勝てるのか |
| 誰の土台に乗っているか（Shopify・App Store・検索 等）・やめにくさ・紹介報酬・前金 | 金が抜ける仕組みの急所 |
| 過去の失敗・死んだ製品・失敗事例の死因 | 地雷を避けるため |
| なぜ当時当たったか・今も通用するか・今やるとどうなるか | 昔話で読者を死地に送らないため |
| 持ち帰れる核心 | 読者が自分の事業に持ち帰る1〜2文 |
| 画像（アイコン・OG画像・App Store画像） | 画像ゼロは手抜きに見える。必須（5章） |
| 出典・権利・食い違い | 信用と法的な安全 |

## 3. 事実と推論（2026-09-30 オーナー決定）
- **事実**: 出典どおりに書く。本人の発言・公表は「本人申告」で採用してよい（本人が言っているなら十分）。記事や第三者の推計は「第三者推計」と印を付ける。
- **推論**: 事実が無い項目は、集めた事実と業界の相場から推して埋める。「推測」「推定」と印を付け、どの事実から推したかを示す。数字には式（例: 売上約$21万 − 運営費約$2万 − 決済手数料約$1万 = 手残り約$18万〜20万）。
- **やってはいけないのは1つだけ**: 推論を事実や本人の発言に見せかけること（「」で括る、〜と語った、存在しない出典）。
- 調べれば公開の事実があるもの（創業年・料金・本人が公表した売上）は、推測で埋める前に一次情報を取りに行く。

## 4. 厳密さはどこまで要るか
- **数字は大体でよい**。「約」「幅」で書き、桁が合っていればよい。料金や運営費を100%合わせることは目的ではない。
- 厳しくするのは2つだけ: ①事実のふりをした嘘 ②出してはいけない物（権利・違法指南・事業と関係ない個人情報）。言い換えや丸めは咎めない。
- 経緯: 2026-09-29〜30 に「出典どおり95%」を目指して監査を14回回し、推論まで作文として消して画面が空になった。正確さの検査を守ることが目的化していた。この失敗を繰り返さない。

## 5. 画像
- 画像ゼロは不可。法的・権利的に大丈夫なものは取る（アイコン、OG画像、App Store画像）。出典を記録し、小さく表示し、削除依頼に応じる。細則は [`MEDIA_ASSETS_AND_PROVENANCE.md`](./MEDIA_ASSETS_AND_PROVENANCE.md)。
- 社内文書の制限を理由に止まらず、法律と権利を調べ直してから判断する。人物写真は使わない。

## 6. 出してよいか（権利と法）
- 事実そのもの（数字・出来事）は著作権で守られない。自分の言葉で書けば商用で出せる。記事の文章・構成は写さない。
- **eBiz Facts（ebizfacts.com）は、利用規約で素材の商用利用・公の表示を禁じている**（2026-09-30 確認）。事例を見つける手がかりとして使い、数字・出来事は本人・公式の一次情報に付け替える。付け替えるまで、その出典しか無い事例は画面に出さない。
- 違法・規約違反・グレーな手口のやり方は、推奨・手順化しない。その会社が実際にやったことを事実として述べるのは可。
- 実在の人・会社について、事実に無い違法の疑いを推測で書かない。

## 7. スタンプ（全部に印を押して保存する）
- 項目ごと: 種類（事実／本人申告／第三者推計／推定／推測）、根拠、出典（どこから持ってきたか）、画面に出してよいか。
- 事例ごと: 画面に出すか、出さないならその理由（公開版の `data/case-display.json`）。
- 手本: [`data/samples/pinboard.stamped.json`](../data/samples/pinboard.stamped.json)（オーナーが「最高」と評価した水準）。

## 8. 薄い事例・難しい事例
- 数字が無い・出典が消えた・事実が少ない事例は、一次情報を1回探し直す。
- 見つからなければ捨てない。保存したまま「データが少ないので画面に出さない」と印を付けて保管し、後の収集で埋まれば出す。
- 第三者の推計しか無い事例（例: JustinGuitar）は、第三者推計と明記すれば規模感として使える。

- 完了は「R2に入り、本番画面に出たか」で測る。途中の工程の成功で進捗を報告しない。
- 大量の調査は Codex（ChatGPT の契約内、最適なモデルと思考量）に回し、Claude は指示・検証・取り込みを担う。
- push・PR・マージ・デプロイ・R2書込みは包括許可（2026-09-30）。いちいち許可を求めない。削除・課金は確認する。
- 会話ごとに担当が分かれる（UIの会話はUIだけ、データの会話はデータだけ）。担当外は頼まれない限り触らない。
- 報告は日本語で、結論から、平易に。項目名の一覧ではなく、実在の1件で「左に項目・右に実際の中身」の実物を見せる。
