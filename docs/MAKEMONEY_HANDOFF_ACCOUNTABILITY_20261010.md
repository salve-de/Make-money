## 3. 目的と製品価値（ユーザー意図。各機能の実採用とは別）

運営者の**長期的な実質利益**を最重要視する。そのためのユーザー価値は、幅広い実在の成功・失敗事例、最新の事業機会、複数事例の共通メカニズム、事業企画、曖昧な自然言語からの実際のWebサイト/SaaS制作、完成品の宣伝/販売/紹介までの連鎖。

2026-10-09の基本案は「事例（無料）・機会（完成済み調査と稼ぎ方の型）・作る（共通プロジェクト）・市場（出品・購入・紹介・記事）」の4入口。事例を経由しない制作、外部で制作した商品の持ち込み、制作をしない紹介者の参加も可能にする。

プロジェクト内に、企画・調査・制作履歴、作品ID、制作会社/外部公開先との許諾済み連携、公開状態、商品下書き・出品同意、正規の販売・紹介状態を保存する方向。ただし、他人のSaaSの本番顧客DBやカード情報、全サーバー運用は原則保持・提供しない。

既存の事例一覧・詳細の承認済みデザイン、本文、画像、章構成を無断で改造しない。収集範囲を狭めず、出典と事実/推論、権利/品質ゲートを維持する。

## 4. 2026-10-10の最後の論点：サーバー移管・他人のSaaS運用を前提にしない

最新の問い：「そもそもユーザーが作ったSaaSの本番サーバー、DB、運営、引き渡しまでMAKEMONEYが担う必要があるのか？」

**提案上の結論**：初めから制作者本人が外部制作/公開会社と直接契約し、完成したサービスは本人のアカウントで稼働させる構成を優先検証する。MAKEMONEYは事例・企画・導線・許可された作品情報・自社ストア/紹介等に集中する。MAKEMONEYがいったん本人のSaaSをホストし、後で所有権とDBを移す仕組みは**最初から必要とはしない**。

比較する方式：
- **A 本人直接契約**：外部AI会社/公開会社と制作者が直接契約。MAKEMONEYは制作仕様・正規導線・許諾済み作品連携・商品掲載。契約/運用負担は一般に小さいが、**サイト内で生成・編集・プレビューを完結できる正式な埋込許諾/OAuth/APIは未確認**。単なる外部リンクでは目標UXが不足する可能性。
- **B MAKEMONEYによるAI制作API再提供**：製作体験をサイト内に統合しやすいが、API会社との商用契約、利用者違反の補償、原価、機密入力、悪用防止の責任が残る。本人名義のホスティングとは分離し得る。
- **C MAKEMONEYによる本番ホスティング**：公開後のサーバー/DB/障害/顧客対応の継続的な運用負担が大きい。**現時点の目的では推奨しない**。必要だと証明された場合のみ別途収益・責任を審査。

**注意**：「A方式を第一候補」とした直前回答は、実証済みの選定結果ではない。Aで完全なサイト内制作が実現できるか未検証であり、旧文書の「Bの外部APIを優先」案との間には比較すべきトレードオフがある。規約/本人所有/API/UX/原価/収益を同条件で検証するまで特定会社を確定しない。

## 5. MAKEMONEYが引き受ける／極力引き受けないこと

引き受ける対象は、MAKEMONEY自体の会員・企画情報・AI連携時に取り扱う入力/認証/権利、事例の権利と正確性、ストア掲載・通報・削除、自社会費、自社が提供する紹介/決済連携に伴う適用法令・契約責任。

極力引き受けない対象は、制作者本人のSaaSの本番サーバー/DBの契約と継続費用、SaaSの個別顧客への提供、個別バグ修正とサポート、顧客情報/購入履歴全件、第三者販売代金の無限定な預りと再送金。

**分離しただけで完全免責にはならない**。自社に原因がある漏洩・誤公開・誤送金・不適切なAPI契約・違反の放置等は、法律と契約に応じ自社責任が発生し得る。
