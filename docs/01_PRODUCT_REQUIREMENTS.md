# プロダクト要件定義

## 1. プロダクトゴール

ユーザーが短時間で、次を完了できること。

1. 未知の金の動きに驚く。
2. 自分との距離を判断する。
3. まだ空いている入口を理解する。
4. 保存、追跡、比較、需要投票のいずれかを行う。
5. 作る側・売る側ならサービスや需要を登録する。

## 2. ユーザーストーリー

### 探索者

- 私は、世の中の面白い儲け方を短時間で眺めたい。
- 私は、1人・低予算・日本向けなど、自分に近い事例だけ見たい。
- 私は、過去の成功談ではなく、まだ間に合う理由を知りたい。
- 私は、後で調べる市場を自分専用に保存したい。

### 実行者

- 私は、市場の金額、需要、競合、価格、入口、リスクを同じページで確認したい。
- 私は、複数の市場を同じ軸で比較したい。
- 私は、実際に欲しがっている人や初期利用者を見つけたい。
- 私は、最初の3つの検証行動を知りたい。

### 掲載者

- 私は、URLだけからサービス情報の下書きを作りたい。
- 私は、顧客、ベータ利用者、提携先、投資家のどれを求めるか明示したい。
- 私は、どの金脈・需要から閲覧されたか知りたい。
- 私は、自社ページをClaimし、根拠レベルを高めたい。

### 需要者

- 私は、欲しいが存在しない商品を投稿したい。
- 私は、「欲しい」と「金を払ってもよい」を分けて表明したい。
- 私は、誰かが作り始めたときに知りたい。

### 発掘者

- 私は、金の動きや成功事例を出典付きで登録したい。
- 私は、自分が早く発見した履歴と信頼度を蓄積したい。

## 3. 機能要件

### P0 — 現在実装済み

- 発見フィード
- 4種類のDBと詳細ページ
- 横断検索
- 絞り込み、並べ替え
- 保存、追跡、比較、反応
- MY GOLDMINE
- サービス、需要、Money Signal投稿
- 所有者Claimリクエスト
- 需要投票
- 掲載者ダッシュボード
- 根拠ランク、スコア説明
- レスポンシブUI、PWA
- ローカル永続化
- 本番DBスキーマとRLS

### P1 — Supabase接続後

- メールOTPログイン
- 公開プロフィール
- ユーザー間で共有される保存・投票・投稿
- 投稿審査キュー
- ドメインメールまたはDNSによるClaim確認
- 市場更新通知、メールダイジェスト
- 公開コレクション
- コメントではなく出典付き訂正提案
- 掲載者への許可制問い合わせ
- 管理画面

### P2 — データが蓄積後

- 内部需要データからOpportunity Gapを自動算出
- 検索・比較行動を集計した匿名Intent
- 価格変更、競合増加、資金移動の時系列
- CSV、API、チームワークスペース
- 早期発見者ランキング
- アフィリエイト・紹介追跡
- 明示されたスポンサーキャンペーン
- 外部データETL

### P3 — 取引層

- ベータ利用者募集
- 制作者・代理店の許可制提案
- 買収関心・非公開資料申請
- 外部M&Aマーケットへの送客
- 必要な法務・本人確認を整えた後の取引支援

## 4. 非機能要件

- 初回表示時に会員登録を要求しない。
- 主要コンテンツはスマートフォンで片手操作できる。
- 金額には必ず種類、通貨、期間、出典、調査日を持たせる。
- 投稿内容はHTMLとして実行されない。
- オーガニック順位とスポンサー表示を分離する。
- 削除・訂正・出典履歴を残す。
- 個人情報を最小限にする。
- DB接続障害時も公開済みデータのキャッシュを表示できる。
- Lighthouse相当のアクセシビリティ、SEO、速度を継続確認する。

## 5. 受け入れ基準

### 発見

- ユーザーがホームから2操作以内に金脈詳細へ到達できる。
- カードだけで金額、人数・規模感、まだ入れる理由、根拠ランクが分かる。
- 保存・比較・追跡は再読み込み後も残る。

### 投稿

- 必須項目が空の場合は送信できない。
- 投稿直後は未確認として区別される。
- 利用者入力は画面上でHTML実行されない。
- 所有者Claimと根拠確認は別状態である。

### 信頼

- A–Dの意味をすべての詳細ページから辿れる。
- 売上、利益、資金調達、契約額、推定市場支出をラベルで区別する。
- スコアの構成要素を個別表示する。
