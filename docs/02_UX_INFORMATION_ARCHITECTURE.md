# UX・情報設計

## 1. 体験の優先順位

DBは裏側であり、初回画面は検索フォームではなく発見フィードにする。

ユーザーが見る順序は次で固定する。

1. 金額または変化
2. 誰が何をしたか
3. 自分との距離
4. まだ残る入口
5. 根拠
6. リスク
7. 次の行動

## 2. 主要ナビゲーション

- **発見する** — 感情と再訪を作るホーム
- **金脈** — Opportunity Window一覧
- **金の動き** — Money Signal一覧
- **サービス** — 実在する商品・事業
- **需要** — 未充足の問題・支払意思
- **ランキング** — 勢い、空白、参入可能性
- **MY GOLDMINE** — 保存、追跡、個人条件
- **掲載する** — サービス、需要、Money Signal投稿
- **掲載者ダッシュボード** — 閲覧と反応

## 3. ホーム

### ヒーロー

- 「次に金持ちになる人は、何を見ているのか。」
- 今日動いた金、急上昇市場、個人参入候補、新規サービス
- 自分向け上位金脈

### フィード

同じカードだけを連続させず、次を混ぜる。

- 無名個人の成功
- 市場への大きな支出
- 急上昇需要
- 競合が不足する分野
- 新しく掲載されたサービス
- 失敗・撤退・支出減少

### カードの必須情報

- Money label
- 何が起きたか
- 誰が払ったか
- まだ入れる理由
- 1人向け、低予算、地域などの条件
- Evidence grade
- 保存、追跡、比較、反応

## 4. Opportunity詳細

上部では可能性を見せ、下部で精査できるようにする。

1. タイトル、金額、総合スコア
2. 勢い、空白、作りやすさ、根拠、鮮度
3. なぜ今起きているか
4. まだ残る入口
5. 誰が支払うか
6. 関連Money Signal
7. 既存サービス
8. 未充足需要
9. 参入条件・期間・予算
10. リスク
11. 今週確認する行動
12. 出典・更新履歴

## 5. 投稿体験

### サービス

最初はURL一つ。残りを下書きし、運営者は修正する。

- 誰の問題か
- 価格
- 地域・言語
- ビジネスモデル
- 求めるIntent
- 関連Opportunity
- 任意の売上・利用者数

### 需要

自由な愚痴ではなく、購入可能な問題として構造化する。

- 誰が困るか
- 何が欲しいか
- 現在の代替
- 代替の不足
- 支払意思
- 痛みの強さ

### Money Signal

- 金額の種類
- 誰が払ったか
- 誰が受け取ったか
- 期間
- 出典URL
- 直接確認か推定か

## 6. 空状態

何もないことをエラーにしない。次の行動を一つだけ示す。

- 保存なし → 金脈を探す
- 比較なし → 比較へ追加する
- 管理サービスなし → URLから掲載する
- 需要なし → 欲しいものを投稿する

## 7. モバイル

- 下部ナビは発見、金脈、金の動き、保存、掲載に限定する。
- 比較表は横スクロールを許可する。
- 右レール情報は本文下または省略する。
- 主要ボタンは44px以上の押下領域を持つ。
- 金額と結論を最初の画面内に置く。

## 8. コピー原則

- 抽象的な「市場機会があります」ではなく、「誰が何へいくら払った」を書く。
- 「必ず稼げる」「残り1枠」など根拠のない断定は使わない。
- 可能性を弱める長い注意書きをカード上部へ置かない。
- ただし、推定・自己申告・資金調達など数字の意味は隠さない。
