# 収集要件（Universal Foundation連携）

Status: **Make-Moneyの収集・表示契約**

## 1. 入口を狭めず、信頼状態を分ける

出典は収集・保存・表示の必須条件ではない。出典がない候補も、分かる範囲の会社名、人物、日付、行動、金額、利益、コスト、不明点を保存し、「未確認」「出典未取得」と表示する。

出典・根拠の強さは、検証済み表示、特集昇格、ランキング、アラート、自動判断の条件である。候補を拾う条件ではない。

この契約に書いた項目はMake-Moneyで優先して表示・分析する範囲であり、Universal Foundationが蓄積する情報の上限ではない。事業・金・顧客・運営・市場に関係する追加情報を見つけた場合、現在の画面で不要でも捨てず、元の観測文と不明点を保存する。型が未定義の情報はraw/unclassifiedとしてUniversal側へ残し、後から別プロジェクトが利用できるようにする。

- 出典あり: 出典、取得日、何を支えるかを表示する。
- 出典なし: `UNVERIFIED` / 「出典未取得」と表示し、確定実績として扱わない。
- 推定: 推定方法、範囲、対象期間を表示する。
- 不明: 不明のまま保持し、推測で埋めない。
- 後から根拠が得られた場合: 元の候補を消さず、根拠と検証状態を追補する。

共通データ項目の全体像は [Universal Foundationの収集基準](https://github.com/salve-de/universal-foundation/blob/main/docs/UNIVERSAL_COLLECTION_BASELINE.md) と [このプロジェクトのデータ収集契約](./08_COLLECTION_CONTRACT.md) を正とする。

Universal Foundationの完全化条件は [UNIVERSAL_COMPLETION_REQUIREMENTS.md（PR #3）](https://github.com/salve-de/universal-foundation/blob/codex/universal-collection-contract-20260906/docs/UNIVERSAL_COMPLETION_REQUIREMENTS.md) に定義する。このプロジェクトはそのうち `business-opportunity.v1` の消費者であり、共通コアの所有者ではない。Make-Moneyで必要な利益・コスト・顧客・集客・運営負担はこの契約で優先し、会計諸表・市場データ・個人家計の完全なデータモデルはUniversal側の別拡張として扱う。

## 2. 全体として集める情報

### 主体

会社、サービス、商品、人物、創業者、運営者、顧客、支払者、受取者、競合、プラットフォームの正式名称、別名、ドメイン、所在地、創業者、チーム規模、現在の状態。

### 行動と時系列

ローンチ、最初の販売、最初の顧客、価格変更、集客施策、急伸、採用、提携、買収、縮小、終了。各項目に「誰が」「いつ」「何をしたか」を結び付け、発生日、観測日、公開日を区別する。

### 金の動き

支払者、受取者、目的、金額種別、金額、通貨、単発/継続、期間、対象範囲。売上、MRR、ARR、GMV、資金調達、契約額、買収額、広告費、データ売上、返金、手数料を混同しない。

### 利益とコスト（最優先）

売上だけで終わらせず、分かる範囲で次を別々に集める。

- 売上原価、粗利益
- 営業費用、営業利益
- 税引前利益、純利益
- 利益率（分子、分母、期間、対象範囲付き）
- 決済、サーバー/API、広告、外注、人件費、返金、税、初期投資
- 創業者・所有者の個人手取り、口座着金

個人手取りは直接確認できる場合だけ記録する。「売上−決済手数料」や推測値を手取り・純利益として表示しない。ピーク、最新、現在値も別の観測として残す。

### 顧客・集客・運営

誰が払うか、顧客の痛み・用途・代替手段・支払意思、最初の顧客・10人・100人、初期チャネル、急伸のきっかけ、現在のチャネル、継続率・解約・紹介、創業者の背景、作業時間、手動対応、外注、自動化、必要資本。

### 技術・競合・リスク

フロントエンド、バックエンド、DB、ホスティング、決済、分析、メール、自動化、AI/APIと、それぞれの確認状態。直接競合、代替、価格差、プラットフォーム/API/決済/規制依存、創業者集中、失敗・縮小・終了リスク。

## 3. Make-Moneyでの最低表示

同じ事例から、最低限次を辿れるようにする。

1. 会社・サービス名、創業者・実行者
2. いつ、誰が、何をしたか
3. 誰から誰へ、何の対価として金が動いたか
4. 売上、利益、コスト、利益率、手取り（種類・通貨・期間付き）
5. 顧客、価格、最初の顧客獲得経路
6. 使用ツール、運営負担、競合・依存、失敗・撤退リスク
7. 出典の有無、取得日、信頼状態

Hook、4 STAGES、Buyer Psychology、Money Machine、Moat、Fragility、White Space、Opportunity Scoreは、上記の事実・主張から生成する派生出力であり、元データと分離する。

## 4. 受け入れ条件

- 出典なしの候補を登録・保存・一覧表示・詳細表示できる。
- 出典なしの候補には「未確認」「出典未取得」が常に表示される。
- 未確認の数字を確定実績、成功保証、検証済みランキング根拠として表示しない。
- 売上、利益、GMV、資金調達、契約額、コスト、手取りを別項目として表示できる。
- 既知の金額に種類、通貨、期間または時点、対象範囲、報告/観測/推定状態がある。
- 「誰が・いつ・何をしたか」と「誰から誰へ・いくら」が同じ事例へ辿れる。
- 新しい出典、数字、訂正、反対情報を追記でき、過去の観測を消さない。
- 未知の項目を、AIの推測で埋めない。
