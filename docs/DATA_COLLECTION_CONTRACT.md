# データ収集契約（Universal Foundation連携）

## 目的

このプロジェクトは、Make-Money専用の記事だけでなく、Idea Spark、GOLDMINE、投資・買収判断などへ再利用できる事業データを蓄積する。画面は出口の一つであり、正規化されたデータと更新履歴を資産として残す。

全プロジェクト共通の正本は [Universal Foundationの収集基準](https://github.com/salve-de/universal-foundation/blob/main/docs/UNIVERSAL_COLLECTION_BASELINE.md) とし、この文書ではMake-Moneyでの表示・運用へ落とし込む。

何を調査対象にするかは、共通基準に加えて [Make-Money / business-case 収集対象の完全目録](./MAKE_MONEY_COLLECTION_SCOPE.md) で固定する。9情報源レーン、12領域、4つの表に出にくい領域、5つの暗部パラメータ、3つの盲点、時間軸、手残りのウォーターフォール、未知値の状態を省略しない。画面に未表示の事実も捨てない。

## 1. 収集と信頼度を分離する

出典の有無を、収集・保存・表示の絶対条件にしない。出典が見つからない情報も候補として保存し、後から根拠を追加できる状態にする。

| 状態 | 収集・保存 | 表示 | 検証済み扱い |
| --- | --- | --- | --- |
| 出典あり | 可 | 出典と取得日を表示 | 根拠が主張を支える場合のみ可 |
| 出典なし・発言者/観測内容あり | 可 | 「未確認」「出典未取得」と表示 | 不可 |
| 推定 | 可 | 推定方法・範囲を表示 | 確定値としては不可 |
| 不明 | 可 | 「不明」と表示 | 不可 |

出典なしの候補を捨てない。ただし、未確認の数字を確定実績、成功保証、推薦根拠として表示しない。新しい出典は既存レコードへの上書きではなく、追補・訂正履歴として追加する。

## 2. 全プロジェクト共通で集める情報

### A. 主体（誰・何）

- 会社、サービス、商品、人物、顧客、支払者、受取者、競合、プラットフォーム
- 正式名称、別名、ドメイン、識別子、所在地、創業者・運営者、チーム規模
- 現在の状態（稼働、買収、縮小、終了、不明）と確認時点

### B. 行動と時系列（いつ・何をした・今も勝てるか）

- ローンチ年、初動獲得期、価格変更、集客施策、成長、採用、提携、買収、縮小、終了
- データ観測期（いつの時点の売上・コスト・指標データか）
- 時代背景（当時なぜその手口が通用したのかのマクロ・プラットフォーム・規制環境）
- 現在の賞味期限・再現性判定（`ACTIVE_PLAYBOOK` 現在も有効 / `RISING_WAVE` 急上昇トレンド最盛期 / `MATURED_MOAT` 先行者堀で困難 / `HISTORICAL_WINDOW` 時代限定で再現不能 / `EVOLVING_BARRIER` 技術進化で特化必須）
- 今やるとどうなるかの客観分析（API価格改定、SEO独占、モデルコモディティ化などデータ根拠による現在の勝敗判定）
- 各イベントの発生日、観測日、公開日、説明、関係する主体
- 最新値だけでなく、過去値・ピーク値・現在値を別レコードで保持

### C. 金の動き（誰から誰へ、何のために、いくら）

- 支払者、受取者、目的、金額種別、金額、通貨、期間、単発/継続、対象範囲
- 売上（revenue）、MRR、ARR、GMV、資金調達、契約額、買収額、広告費、データ売上、返金、手数料
- 不明な項目は空欄や推測で埋めず、不明として保持する

### D. 利益とコスト（最優先）

- 売上、売上原価、粗利益、営業費用、営業利益、税引前利益、純利益、利益率
- 決済手数料、サーバー/API費、広告費、外注費、人件費、返金、税引き、初期投資
- 創業者の個人手取り・口座着金は、直接確認できる場合だけ別項目で保持する
- 「売上」「利益」「利益率」「手取り」「推定利益」を同じ数字として扱わない

### E. 顧客・需要・集客

- 誰が払うか、顧客の役割・地域・規模、利用目的、痛み、代替手段、支払意思
- 最初の顧客、最初の10人/100人、初期チャネル、急伸した投稿・イベント、現在の主要チャネル
- チャネル依存、継続率、解約、リピート、紹介、広告依存

### F. 運営・技術・競争

- 創業者の背景、失敗、作業時間、手動対応、サポート、外注、自動化、必要資本
- フロントエンド、バックエンド、DB、ホスティング、決済、分析、メール、AI/API、依存サービス
- 直接競合、代替、価格差、プラットフォーム/API/決済/規制/人物集中リスク

### G. 根拠と不確実性

- 出典がある場合のURL、タイトル、発行者・発言者、公開日、取得日、取得内容、権利状態
- 出典がない場合の収集経路、発言者・観測者、観測日、未確認理由
- `reported / observed / estimated / inferred / unknown`
- `SUPPORTED / CONFLICTED / UNVERIFIED / SUPERSEDED / RETRACTED`

## 3. Make-Moneyの表示要件

Make-Moneyでは、候補を拾う入口を狭めない。最低限、分かる範囲で次を同じ事例に結び付ける。

1. 会社・サービス名、創業者・実行者
2. いつ、何をしたか
3. 誰から誰へ、何の対価として金が動いたか
4. 売上、利益、コスト、利益率、手取り（分かる項目だけ。種類と期間を明示）
5. 顧客、価格、最初の顧客獲得経路
6. 使用ツール、運営負担、競合・依存、失敗・撤退リスク
7. 出典の有無と信頼状態

出典なしの事例も一覧・詳細に出せる。ただしカードと詳細の両方に「未確認」「出典未取得」を表示し、確定値のような色・文言・ランキング根拠にしない。Hook、4 STAGES、Buyer Psychology、Moat、Opportunityは、収集した事実から作る派生情報として別管理する。

## 4. 更新ルール

- 同じ主体の新しい売上・利益・価格・状態は、過去値を消さず時系列で追加する。
- 出典なしの候補に後から根拠が付いた場合、元の未確認レコードを消さず、根拠・検証状態を追補する。
- 反対の数字や説明は削除せず、競合状態として残す。
- 画面上の「代表値」と、裏側の全観測値を分離する。
- AIの解釈を、本人の発言や観測事実へ書き戻さない。

## 5. 受け入れ条件

- 出典なしの候補を登録・保存・表示できる。
- 出典なしの候補が検証済み・確定実績として誤表示されない。
- 利益とコストを売上・GMV・資金調達から識別できる。
- 各金額に種類、通貨、期間または時点、推定/報告/観測状態がある。
- 「誰が・いつ・何をしたか」と「誰から誰へ・いくら」が同じ主体・イベントへ辿れる。
- 新しい出典・数字・訂正を追記でき、過去の観測を破壊しない。
