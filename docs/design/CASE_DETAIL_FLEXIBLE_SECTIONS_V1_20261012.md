# MAKEMONEY — 事例詳細の共通目次と可変本文

2026-10-12。オーナー指示「じゃあそれでやるようにして」を受けた設計・実装の基準。**既存の事例一覧と画面構造を勝手に改変しない。** 本文と図解は調査時に書いた原稿を保持する。本書は設計方針であり、コード反映・R2保存・本番公開・大量件数性能の完了報告ではない。

## 1. 決定

- 上部の目次は **概要 / 仕組み / お金 / 集客 / 運営 / 経緯 / 出典** を基本とする。毎回のAIが勝手なラベルを新設しない。表示中の全項目を1行固定し、横送り・折りたたみ・全章ボタンで隠さない。
- 目次を押すと該当する**共通大分類**の見出しへ移動し、スクロール中の分類を強調する。事例を切り替えれば強調・リンク・記事の状態も切り替える。
- 本文では「概要」等の共通大見出しの下に、**その事例だけに当てはまる具体的な小見出し**を置く。例：Tallyの「Tallyは何を提供し、誰がお金を払うのか」。
- 小見出しの数・原稿量・画像・図表の種類と位置・出典は事例ごとに可変。類似の話が多い場合は小見出しで整理し、大分類のタブを増殖させない。
- 収集データがない章は記事にも目次にも出さない。7章を全件必須にしない。「未確認」と空枠を並べるために事実を捏造しない。
- 表示の分類は**収集・保存の項目の上限ではない**。Foundationの領域、既存収集台帳、自由観測、根拠、権利、欠損はそのまま保持。記事を取り込むとき再要約せず、調査担当が原典を理解した状態で執筆した版を使う。

## 2. 各共通タブの意味と境界

| 分類ID（将来の案） | 表示 | 読者が知ること |
| --- | --- | --- |
| overview | 概要 | 何を誰に提供する商売か、初めに見るべき実績・使い道 |
| mechanism | 仕組み | なぜ買われるか、サービスの特徴、参加者の関係、商売が成立する工夫 |
| money | お金 | 誰が何にいくら払うか、無料と有料の境界、価格、売上・利益・費用・資金の流れ |
| acquisition | 集客 | 初期顧客、検索・紹介・営業・広告・提携、購入と継続 |
| operations | 運営 | 誰がどう製造・提供・納品・保守するか、設備、外注、技術・業務負担 |
| history | 経緯 | 創業、転機、失敗、ピボット、買収、撤退、現況 |
| sources | 出典 | 根拠の発行元とリンク、数字の判断に必要な条件 |

「仕組み」と「運営」を混同しない。仕組みは価値と成立メカニズム、運営は実際に提供し続ける仕事。「お金」は従来の「収益」を拡張した言葉で、赤字・未収益・資金調達・複数の収入源にも対応する。「集客」と「経緯」の同一エピソードを二重掲載しない。

## 3. 画面の例

共通タブ「概要」の下：
- Tally：Tallyは何を提供し、誰がお金を払うのか
- The Woobles：初心者向けの編み物キットを販売する
- Flightradar24：航空機の位置を地図で見られるサービス

共通タブ「仕組み」の下：
- Tally：無料フォームから次の利用者が増える仕組み
- The Woobles：初めての人がつまずく工程を先に済ませる
- Flightradar24：各地の協力者から航空機の信号を集める

同じ「お金」でも複数の顧客・商品・課金源があれば、複数の小見出しや図解で説明する。大分類に押し込むために文章を削らない。

## 4. 例外と拡張

- 無い情報を無理に書かず、調査状態と欠損理由は内部に保存する。利益不明でも価格・費用の話が根拠付きであるなら「お金」を表示してよい。
- 重要な情報が7分類のどれにも自然に入らない場合、**削除も強引な当てはめも禁止**。根拠ID付きで未分類として保持し、編集・分類規則を再検討する。必要ならtaxonomyをバージョン更新する。準備中の情報を公開済み扱いにしない。
- 名称や見出しを改稿しても安定したsection/item IDと根拠参照を保持。未知の事例で専用HTML/JavaScriptの自由実行を許さず、共通レンダラーの登録済みブロック（文章・指標・表・図解・実画面・年表・比較図等）で表現する。
- 一つの事業の経営全体と一つの製品、売上と取扱高、累計と年間、本人申告と決算原本を混同しない。読者に無関係な検査メモを画面へ並べず、数値の意味を決める条件だけ明確にする。

## 5. 現行コードとの実装差

## 6. 合格条件

1. 最初の3件の原稿23小節・元図解6点・出典が失われず、共通タブ7種の下で固有の見出しが出ること。
2. 表示内容のない大分類は目次・本文の両方から消え、章移動とスクロール強調は残ること。
3. 320/390/768/1024/1280/1440pxで1行、ラベル欠けなし、見出し位置が固定目次と重ならないこと。キーボード・支援技術・図の拡大も確認。
4. 異業種20〜30事例（SaaS、物販、店舗、製造、仲介、広告、インフラ、受託、ライセンス、非営利、赤字・撤退、複合事業）を通し、分類不能・誤分類・原稿脱落・記事の読みやすさを検査してから大規模投入。
5. 1万・100万・1億事例の索引、検索、ページング、詳細オンデマンド取得、保存、キャッシュ、権利削除、コスト・障害耐性は**別途段階的に負荷試験**する。7分類を共通化しただけで1億件対応を実証したとしない。
