# 決まった画面の形の台帳

**画面を変える前に必ず読む。ここにある形を変える時は、作る前にオーナーに聞く。**

作られた日: 2026-10-09。きっかけの事故: 事例ページの見本を作る時、オーナーが前提にしていた「画像を横に並べて左右の矢印で送る欄」（`EntityMediaGallery`）を使わず、指揮が「写真1枚を右に置く枠」へ勝手に置き換えた。オーナーの言葉は「決まったものを無視して実装するのはクソ、インシデント」。注意書きや記憶では防げなかったので、この台帳と試験で止める。

## 使い方（人もAIも同じ）
1. 画面（見た目・並び・部品・章・図）に触る前に、この台帳の全件を読む。
2. 同じ役目の既存の部品があれば、それを使う。外部の手本（他社の画面など）は、足りない所を埋めるためにだけ使い、ここにある形を上書きしない。
3. ここにある形を変えたい時の手順（全件共通）:
   1. 作る前に、オーナーに1行で聞く（何を・なぜ変えたいか）。
   2. オーナーが OK した言葉と日付を、その件の「決めた日」「オーナーの言葉か根拠」に書く。
   3. 同じ変更の中で、守る試験（`src/features/company-inspector/ui/decided-ui.test.tsx`）を新しい形に直す。試験だけを弱めて通さない。
4. 新しく決まった形は、決まったその日にここへ1件足す（形・部品・日付・オーナーの言葉・試験）。
5. 守っているかは、`pnpm lint`（コミット前に走る）と `pnpm test` が試験で止める。

  - **札の出し方**: 一覧の右の「種類」の列（PC。列に収まらない分は折り返して2段まで）、左右に分けた一覧とスマホの一覧は説明の下、詳細は見出しの名前（と年）の右に、「分野・事業の形・売る相手・(AI)」の順で、薄い塗りの小さな札（罫線なし・背景 `term-line`・文字 `term-sub`・12px・高さ20px）。一覧の札は全部押せて、押すとその言葉で絞り込む。列の見出しは「種類」。「収集事例」などの運営の印と、事例ごとの自由な言葉（`entity.tags`）、説明文から決める分野（`genreLabel`）、`fact-lines` の札は札に出さない。タグが無い事例は札を出さない（公開データの作成が、タグの無い事例を出さない）。
