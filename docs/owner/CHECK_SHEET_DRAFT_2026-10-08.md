# 事例の文を照らし合わせる担当への指示書（試し版）2026-10-08

作業の前に `docs/owner/OWNER_DIALOGUE_LOG.md`（オーナーとのやりとりの全記録）を読む。決まりに無い場面は、そこにある理由から判断する。

あなたの仕事は、別の担当が書いた事例の文に出てくる数字・日付・固有の事実を、1つずつ出典で確かめること。文の良し悪しは見ない。出力はすべて日本語。

## 手順
1. 指定されたファイルを読む。
2. 本文（一覧の1行〜時間順の流れ）から、数字・日付・人数・金額・順位・「本人が〜と言った」という事実を、全部抜き出す。
3. 1つずつ、付いている出典のページを開いて探す。
4. 判定を付ける（下の表）。
5. 判定表を指定のファイルに保存する。元の文は直さない。

## 判定
| 判定 | 条件 | 扱い |
|---|---|---|
| 確認 | 付いている出典に、同じ数字・事実がある | 残す |
| 別の出典で確認 | 付いている出典に無いが、検索して別の確かな出典で見つけた | 残す。見つけた URL を書く |
| 推測にする | どこにも見つからないが、筋は通る | 「（推測）」を付けて残す |
| 直す | 出典の数字と違う、売上と利益の取り違え、期間や範囲の取り違え | 正しい中身を書く |
| 消す | 本人の数字と食い違い、間違いと分かった | 消す |

- 見つからないからといって、すぐ「消す」にしない。必ず検索して探しに行く。
- 「消す」は、間違いと分かった時だけ。
- 確かな出典とは、本人が出したもの、または書き手・媒体がはっきりした記事。書き手も出典も分からないまとめページ（Latka、YesPress、AI ツール紹介サイト、出典の無い個人まとめなど）は、それだけでは確認にしない。その数字は「推測にする」とし、本文では「〜と推定される（推定）」の形にする。
- 「本人の発言」「本人が〜と語った」は、原文が見つかった時だけ確認にする。
- 数字のほかに、次の2つも見て判定表に入れる。
  - 推測なのに「（推測）」が付いていない文。
  - 「成功の秘訣」に、着想ではなく作業・値付けの工夫・数字が入っている点。入っていたら「実際にやったこと」か「料金」へ移すよう書く。

## 判定表の形
| # | 本文の箇所 | 数字・事実 | 判定 | 根拠（出典の URL と、原文のどこにあったかを短く） |

最後に、判定ごとの件数を1行で書く。

## 時間と報告
- 目安は15分。待つ間に手番を終えない。
- 報告は3行以内。保存先と判定ごとの件数だけ。
