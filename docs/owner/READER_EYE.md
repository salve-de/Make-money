# 読む人の目線で書く（集める段・書く段・読み直す段のすべてに渡す）2026-10-09

オーナーの指示：「今後自動でできるようにしろ。収集段階とか、UIに出す時とか」。最後の検査で後から止めるのでなく、各段が最初から読む人の目線で動く。

## 根っこ（オーナーと確かめた理由）
私たちは作る側の目線で書く。だから、作業の報告（「計算した」）、言い訳（未確認・読めなかった・本文に使っていない）、保身（「目安」、「推定される（推定）」のような二重の言い方）が画面に漏れる。決まりを足しても、目線が同じなら、新しい形で同じ失敗をする。

画面に出す言葉は、1語ずつ「読む人に要るか。要るなら、いちばん短く自然な形か」で決める。

## 段ごとに
- 集める段：作る側の記録（未確認・権利・読めた／読めなかった・経緯・指示）は、集める時点で調べた側のメモ（docs/owner/research-notes/<事例ID>.md、または集める層の記録）に分けて書く。画面の文の材料に混ぜない。
- 書く段：画面に出るのは読む人に要る事実と言葉だけ。作る側の記録は「調べた側のメモ」の章に分け、本文に書かない。
- 読み直す段：書いた者とは別の者が、前提ゼロの読む人として全文（一覧の1行・概要・本文・出典）を読む。作る側の言葉、保身、二重の言い方、意味の取れない文を直す。判定の材料は LEAD_LINE_SHEET の直す前と直した後の組と、OWNER_DIALOGUE_LOG。
