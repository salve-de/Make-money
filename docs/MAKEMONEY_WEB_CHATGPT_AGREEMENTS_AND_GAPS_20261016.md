# MAKEMONEY｜過去Web ChatGPTの合意と現行収集の差分（2026-10-16）

> **位置付け：引き継ぎ用の読取監査記録。新しい収集・編集・画像権利ルールではない。** 既存の毎時オートメーション、画像権利判定、公開設定、既存原本を変更していない。過去の全チャットを逐語的に網羅したという主張もしない。確認できた過去Web ChatGPT会話、GitHubの現物、Libraryの実ZIPを区別して記録する。

## 1. オーナーが最終的に実現したいこと

- MAKEMONEYで世界の実在する商売・稼ぎ方を幅広く発掘し、「何を、誰が、なぜ買い、最初の客をどう得て、実際にどう売れ、どう成長し、どれだけの成果を出したか」を、根拠ある事実と自然で分かりやすい日本語で読者に示す。運営者の長期的な実利益と、読者が繰り返し使いたい価値を最上位に置く。
- 調査は幅広く（商品/顧客/収益/初期資源/初売り/集客/拡大/運営/数字/転機等）、**調査と記事作成を一体で**行う。記事に使わない有用な事実・根拠は別の研究原本に残す。画面の基本UIはPR #224のPlausibleを参照するが、段落量や図解数を事例間で固定しない。
- 記事本文の分類は「概要／仕組み／お金／集客／運営／経緯／成功の理由」、末尾に別枠「出典」。利用可能な根拠のない章を水増ししない。
- 定期収集は可能なら毎時。現実に安定稼働する経路でChatGPT Library「Make money」へ原稿・出典・図を蓄積する。**オーナーはZIPの繰り返しダウンロード・移動・添付をせず、Codexへ一言で未取込分を受け渡したい**。CodexがLibraryから実ZIPバイトを直接取得できるかは実Codex環境で未実証であり、実装済みとは言わない。原稿の品質、Library保存、Codex受領、本番公開は別の判定。Google Drive保存は採用しない。Scheduled→R2/GitHubへの実記事自動書込は失敗/拒否の履歴があり、できると断定しない。本番公開・課金・デプロイは勝手にしない。

## 2. 過去に実際に決めた「文章」

- **2026-10-04前後のWeb ChatGPT会話**：意味のないAI一般論、直訳、長い内部監査メモ、成功と無関係な赤字・リスクの羅列、事実の断片を後からつなぐ原稿は不可。読み手の疑問から逆算して取材し、最初の客・売り方・お金・成長を具体的に伝える。
- **2026-10-12のWeb ChatGPT会話**：「短くても薄くしない」。短い段落・箇条書き・番号付き説明・表・年表・図解を組み合わせて視覚的に読みやすくし、文章ばかりで長々とした表示にしない。一文結論や強いリードを重視する。**情報を削ることや一律の字数上限を決めることとは違う**。
- **2026-10-15〜16の訂正と正本**：必要な具体的事実を落として短縮しない。読者向け本文と長い研究原本・出典/権利/QA記録を分離し、冗長な本文は編集する。文章は人間が全文を読み直す。現行正本の「短さ自体を目標にしない」と矛盾しない。
- 参考原典：[2026-10-16編集・収集SSOT §5〜7](https://github.com/salve-de/Make-money/blob/docs/makemoney-owner-reality-20261015/docs/MAKEMONEY_CASE_RESEARCH_EDITORIAL_SSOT_20261016.md)、[同Runbook](https://github.com/salve-de/Make-money/blob/docs/makemoney-owner-reality-20261015/docs/MAKEMONEY_COLLECTOR_START_HERE_20261016.md)。

## 3. 過去に実際に決めた「画像・アイコン」と権利の区別

- **2026-09-29オーナー決定**：**「画像は必須。取れるものは取る」**。対象は公式サイトのアイコン/プレビュー、製品画像・画面、App Storeのアイコン・ストア画面写真等。収集画像は出所・サイズ・バイト/ハッシュと権利判断を区別して台帳へ残す。**取得済み原本（非公開）と、商用公開できる画像は別物**。自動取得はまず held、表示は根拠と判断があるものだけ。
- **2026-10-02オーナー決定**：製品を実際に使う画面・出力例・実物を最優先。App Storeの画面→公式サイトの製品画面→一覧用の小さなアイコンの順。**favicon・ロゴや広告バナーだけを集めて製品画像収集の完了とはしない**。
- **2026-10-16現行の権利条件**：他社画像の公開・第三者への無断転載を、閲覧できるだけで許可と見なさない。掲載権未確認の写真は無断でZIPへ転載しない。候補URL・権利メモを保全することは必要だが、**URLのみを「製品画像の実ファイルを収集済み」と誤報しない**。旧来の非公開取得フローと最新の「転載権未確認ならコピーしない」という表現の運用差は、権利を緩めず既存の媒体規約・用途別判断で照合するべき未解消の差。ユーザーが無許諾の公開転載を許可したという意味ではない。
- 正本・当時の決定原文：[MEDIA_ASSETS_AND_PROVENANCE.md §§0,2.2](https://github.com/salve-de/Make-money/blob/main/docs/MEDIA_ASSETS_AND_PROVENANCE.md)、[MEDIA_THUMBNAIL_AND_LIKENESS_POLICY.md](https://github.com/salve-de/Make-money/blob/main/docs/MEDIA_THUMBNAIL_AND_LIKENESS_POLICY.md)、[2026-10-16 SSOT §8](https://github.com/salve-de/Make-money/blob/docs/makemoney-owner-reality-20261015/docs/MAKEMONEY_CASE_RESEARCH_EDITORIAL_SSOT_20261016.md)。

- これだけでは各画像を合法的・契約上安全に実バイト取得して保存できたかまでは断定できない。ただし、「画像の実体まで収集済み」とは判定できない。各事例で、画像の候補発見、バイト取得の試行/結果、権利判定、公開用画像の可否を混同せず記録する必要がある（**既存の媒体台帳方針の再確認**であって新ルールではない）。
- 記事は約4,500〜7,700字で長さがばらつく。**字数だけで不合格にはしない**。過去の要望は「長い文章を漫然と置くな・短くても内容を薄めるな」。その遵守には実記事全文の重複・情報量・箇条書き/表/図の使い方を確認する必要がある。今回、スマホ実ブラウザでの表示品質は未検証。
- 直近のKitやTuft & Needleは差分ZIP＋追加目録で保存され、旧『MAKEMONEY_まとめてDL_最新版.zip』を毎時上書きする方式ではない。これも運用変更の事実として引き継ぐ。

## 5. 現在の毎時収集指示との差（設定は変更していない）

- 対象：既存の毎時タスク **ID `6ad0f04857208190a175408249eb750c`**、2026-10-16 14:13 JST頃の実行を確認。**有効・毎時、差分ZIP＋差分目録**を保存する現行契約。
- 現行画像指示の実際の範囲は「公式の製品/画面写真の参照URL・権利者・利用条件を調べ、権利未確認ならコピーしない、自作SVGは必要時だけ作る」。**2026-09-29/10-02の『取得可能な公式実画像・アイコンを取得する』工程・結果を納品できたという証拠は、この指示と上記ZIPからは得られない**。URL記載のみの納品と画像バイト納品の混同が今回の争点。
- 現行本文指示は「自然な日本語、主要KPI最大4、短いリード、必要な表・箇条書き・図、不要な冗長さ削減、重要事実を削らない」で、おおむね既往の編集原則と一致。**問題は本文が実際に冗長でないかの原稿レベルの判定**であり、別の固定字数制限を新設することではない。
- 収集タスクは今回**変更していない**。画像ダウンロード方針の拡大、掲載許諾の拡大、Codexの代替保存経路、新Task/Cronの作成をこの文書で承認しない。
