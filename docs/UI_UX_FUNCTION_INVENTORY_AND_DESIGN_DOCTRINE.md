# Make-Money UI/UX機能棚卸し・設計憲法

更新日: 2026-09-06  
基準コミット: `6bb99b9`

この文書は、UIを先に装飾するためのスタイルガイドではない。北極星に対して、何を残し、何を統合し、どの情報をどの順番で見せ、何をもって美しいと判定するかを固定するための設計契約である。

## 1. 設計の起点

### ミッション

世界中の金儲けの事実・手口・金額・心理・損益を蓄積し、読者が「誰が、誰から、どうやって、いくら抜いたか」を最短で盗める、最新の資本主義情報端末になる。

### ユーザーが買うもの

ユーザーが買うのは、画面、診断、カード、記事数ではない。

- 他人の財布の構造
- 金が動いた決定的な瞬間
- 原価、価格、利益、手残り
- 顧客の恐怖・見栄・痛み・怠惰を突いた手口
- その手口を自分の手札に移植できる素材
- どこまでが事実で、どこからが推定かという判断材料

「学ぶ」「計画する」「努力する」を主役にしない。主役は、密度の高い事実を見て、欲望と判断を動かすことである。

### 設計判断の5つの質問

すべての機能・画面・文言・装飾は、次の質問を通す。

1. 金儲けの事実または構造を増やすか。
2. 読者が手口を盗める情報を増やすか。
3. 出典、時点、確度を明確にするか。
4. 最新の金の流れを見に戻る理由になるか。
5. PRO、ツール送客、創業支援、M&A、データ提供のいずれかに自然につながるか。

0個なら削除、1個なら統合、2個以上なら中核候補とする。見た目がきれいでも、この判定を通らない機能は残さない。

## 2. 現在の機能棚卸し

### 2.1 ルート

| ルート | 現在の機能 | 設計上の扱い |
|---|---|---|
| `/` | PORTAL、TERMINAL、FINDER、IDEAS、特集、シグナル、ランキングを状態切替 | 主要OSシェル。ただし状態をURLへ昇格する |
| `/finder` | Finder専用ページ、企業詳細モーダル | `/`と重複。将来は単一の武器検索面へ統合 |
| `/success` | 決済完了表示 | 課金後の権限反映と一体化 |

### 2.2 表側の機能

| 機能 | 現在の実装 | 判定 |
|---|---|---|
| 市場ポータル | 指標、TOP5、特集、シグナル、ランキング、ニュースレター | 残す。最新情報の入口へ再編 |
| 企業DB | 企業一覧、規模タブ、並び替え、検索、詳細ドシエ | 残す。裏帳簿の全件検索として強化 |
| 50軸スクリーナー | 多次元条件、ライブ件数、条件適用 | 残す。適職診断ではなく武器検索にする |
| Finder | 6軸推薦、適合度、収益、ツール、コピー文面、PROプレビュー | 残す。ただし推薦理由と証拠を強化 |
| Ideas Vault | カテゴリ、検索、機会詳細、収益構造、ツール、企業リンク | 残す。アイデア集ではなく武器庫に再定義 |
| 特集 | Special CollectionsとCollection Detail | PORTAL内のモードへ統合 |
| シグナル | Market SignalsとSignal Detail | PORTAL内の最新フィードへ統合 |
| ランキング | Leaderboard | PORTALまたはTERMINALのソート・ビューへ統合 |
| ニュースレター | メール登録 | 残す。最新情報の再訪・換金導線 |
| 認証 | Google、メール登録、ログイン、ログアウト | 残す。保存とPRO権限に接続 |
| ブックマーク | APIは存在 | UIと保存状態を接続するまで未完成 |
| 事業掲載申請 | モーダルは存在 | API送信・審査状態と接続するまで非中核 |
| M&A | 入口の構想のみ | データの信用と流動性が成立するまで後段 |

### 2.3 API・データ・課金

| 領域 | 現在の実体 | 現在の問題 | 設計判断 |
|---|---|---|---|
| 企業データ | `TERMINAL_COMPANIES`、`BUSINESS_DATA`、`/api/businesses` | 静的データとAPIが並列 | 表示用の正規化データ契約を1つにする |
| 保存 | `/api/bookmarks` | 保存ボタン・一覧・再訪状態が不足 | 「後で盗む」ための中核機能にする |
| 認証 | Firebase、`/api/user/me` | PRO・保存への接続が不明瞭 | アカウント、保存、権限を同じ状態モデルにする |
| 決済 | `/api/checkout`、`founding-pass`、Stripe webhook | 有料成果物・権限反映の一貫性が未証明 | 実際に解放されるデータと権限を定義する |
| ニュースレター | `/api/newsletter/subscribe` | 比較的接続済み | 最新情報の定期入口として維持 |
| 掲載申請 | `/api/submissions` | UIの送信処理とAPI接続が一致しない | 実接続まで表側の主導線に出さない |
| データ信頼 | `AUDITED_PUBLIC`、`VERIFIED_STRIPE`、`ESTIMATED_MODEL` | 一部バッジはあるが集計・見出しが混在 | すべての数値に確度・期間・出典を付ける |

## 4. 4つの主要面の画面契約

### PORTAL：最新の金脈を浴びる

目的は説明ではなく、最新の金の流れを一瞬で感じさせること。

必須情報:

- 新着・更新時刻
- 誰が、誰から、いくら得ているか
- 売上、粗利、営業利益、手残り、原価
- 直近で変化したシグナル
- 証拠状態
- 次に開ける企業・手口

ポータル上の最初の画面に、自己紹介文、抽象的な理念、同じデータの重複ブロックを積まない。

### TERMINAL：裏帳簿を調べる

企業名を眺める場所ではなく、収益構造を解剖する場所。

詳細では次の順に並べる。

1. 何を売ったか、誰が払ったか。
2. 価格・原価・粗利・手残り。
3. 顧客の心理的急所と販売経路。
4. チーム規模、時間、使用ツール。
5. 成長・失速・売却・停止の時系列。
6. 出典、観測日、推定箇所、未確認箇所。
7. そのまま使える手口・素材。

### FINDER：武器を検索する

診断結果を押し付けるのではなく、全件データから手札に近い構造を探す。

- 50軸の全貌は維持する
- よく使う条件は短い操作で選べる
- 詳細条件は必要時に展開する
- 結果件数と除外理由を示す
- 結果数を恣意的に3件へ制限しない
- 適合度の計算根拠を開示する
- 推薦結果を企業DB・証拠・武器素材へ接続する

### IDEAS_VAULT：武器庫

カードを眺める場所ではなく、実在事例から抜き出した構造・素材の保管庫。

各レコードは次を持つ。

- 元になった企業・事例
- 金が動いた事実
- 市場の歪み
- 支払者と支払理由
- 価格、原価、粗利、手残り
- コピー可能な販売・集客素材
- 事実・観測・推定・解釈・不明の区分
- 関連するTERMINALレコード

「簡単」「月利○万円」といった煽りだけで完結させない。

## 5. レイアウトとビジュアルの規律

### レイアウト

左右2ペイン、縦長、表、インスペクター、オーバーレイのどれを使うかは、情報の仕事で決める。固定形式を神格化しない。

- 比較が仕事なら表・行・列
- 一覧から詳細へ移るならマスター・ディテール
- 最新情報を追うなら時系列フィード
- 1つの証拠を読むならドシエ
- 条件を組み立てるならクエリ面
- 画面を閉じずに一時確認するならインスペクター

### 密度

高密度とは、小さい文字を詰め込むことではない。

- 同じ単位を縦に揃える
- 数値の桁・期間・定義を揃える
- 見出し、データ、出典の階層を明確にする
- 重要でない説明を削る
- 1画面内で比較可能な量に制限する
- 密度を上げても主要操作のタップ領域は削らない

### 色・タイポグラフィ

- 背景は白・黒・スレートを基本とする
- 緑は実績・上昇、黄は推定・注意、赤は損失・危険、青は外部参照に限定
- 色をブランド装飾やランキング演出に乱用しない
- 英語ラベルは補助。日本語の意味を隠さない
- 数字は等幅・桁揃え・単位分離
- 本文は読み切れるサイズを確保する
- `select-none` を全体へ適用せず、ドシエの数字や文章は選択可能にする

### 禁止するもの

- 意味のないカードの連続
- 長い説明文で数字を埋めること
- 確度の違う情報を同じバッジで表示すること
- 0件なのに別のレコードを表示すること
- 最新性を示さない「速報」「実査済み」表記
- クリックできるのにリンク・ボタンとして振る舞わない要素
- 画面ごとに異なる閉じる、戻る、保存の作法
- 見た目のためだけの無限ティッカー

## 6. 状態・データ・信頼性の契約

### 数値の表示契約

すべての金額・率・件数は、少なくとも次を同伴させる。

```text
value / unit / period / as-of / evidence-state / source / definition
```

年間売上を月商として表示する場合は、実績月商と分けて「年額÷12の算出値」と表示する。「単独最高月商」のように、集計条件とラベルがずれる表示は禁止する。

### 状態契約

- フィルター結果が0件なら、詳細は必ず空状態になる
- 選択中レコードが結果から外れたら選択を解除する
- 画面、検索条件、選択ID、並び順はURLまたは保存可能状態にする
- 戻る、進む、リロード、共有で意味が変わらない
- 集計は表示対象と同じ集合を使う
- 信頼区分の異なる値を集計する場合、集計の定義を明示する

### 証拠契約

`AUDITED_PUBLIC`、`VERIFIED_STRIPE`、`ESTIMATED_MODEL` の3区分だけで終わらせず、表示単位では `reported`、`observed`、`estimated`、`inferred`、`unknown` を持てるようにする。

推定値を排除するのではなく、推定値を推定値として価値ある情報にする。出典がないことは保存禁止の理由ではないが、確定実績や推薦根拠へ昇格させる理由にもならない。

## 7. 操作・アクセシビリティ・レスポンシブ

### 操作

- クリック可能な行はキーボードでも操作できる
- ブランドはリンクまたはボタンにする
- 戻る、検索解除、条件解除、保存、比較を常に同じ場所と名称にする
- コピー操作は成功・失敗を明示する
- 0件には「解除」だけでなく、どの条件が効いているかを示す

### 画面幅

#### 390px

- 最新ネタ、主要数値、検索、詳細への導線を最優先
- 左右の固定幅をそのまま縮めない
- 一覧と詳細は切替またはシートにする
- 表は重要列だけに絞り、残りは詳細へ移す

#### 768px

- 比較と詳細を同時に保てる場合だけ2列を使う
- 使えない場合は一覧優先にして詳細を展開する

#### 1280px以上

- 全件の鳥瞰、比較、詳細、出典を同時に扱える
- 余白は装飾ではなく、意味の境界に使う

## 8. 換金導線

課金は「画面を隠す」ことではなく、価値の深度に接続する。

無料で見せるもの:

- 最新の金の流れ
- 主要な売上・利益・手口
- レコードの存在と概要
- 確度の表示

有料で提供するもの:

- 非公開または深い証拠
- 契約・価格・原価の詳細
- 生データ、CSV、API
- コピー可能な素材
- ツールの実装情報
- 企業比較・保存・アラート

有料ボタンの近くには、価格だけでなく「何の情報が、どの深度まで解放されるか」を書く。PRO、法人、M&A、アフィリエイトを同じ画面で競合させない。

## 9. 実装の順番

1. この棚卸しに基づき、各機能の接続表を確定する。
2. 旧部品、重複部品、未接続APIを整理する。
3. 4画面の画面契約と状態遷移を確定する。
4. データ表示契約と証拠状態を統一する。
5. URL、保存、比較、空状態を実装する。
6. 低忠実度の画面構成を各画面幅で確認する。
7. タイポグラフィ、色、密度、モーションを適用する。
8. 実装後に匿名・ログイン済み・0件・再訪・課金前後を検証する。

新しい画面や機能を足す場合、既存のどの機能を統合・削除するかを同時に記録する。機能数だけを増やすPRは禁止する。

## 10. 完成判定

### 情報価値

- 1秒で最新の金の流れが分かる
- 5秒で主要数値と確度が分かる
- 30秒で1つの収益構造が分かる
- 1クリックで証拠、詳細、使える素材へ移れる

### 状態整合

- 0件時にゾンビ詳細が出ない
- フィルター後の集計が表示対象と一致する
- 推定値と実査値が混ざらない
- リロード・戻る・共有で状態が壊れない

### 品質

- 390px、768px、1280pxで主要導線が成立する
- キーボード操作とフォーカスが成立する
- Lintが通る
- Production buildが通る
- 実ブラウザで匿名利用から保存・課金・再訪まで確認できる

この文書の目的は、UIを固定することではない。北極星を守るために、形式を捨てる判断基準を持つことである。
