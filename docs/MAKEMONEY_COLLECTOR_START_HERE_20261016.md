## 0. 担当・ゴール
- **対象：** 世界の実在する価値ある成功商売。国、業態、規模を固定せず、初売り・実際の拡大過程・収益構造に固有の情報がある事例を選ぶ。未収集/改訂の区別と重複を照合。
- **収集AI（ChatGPT毎時、ChatGPT単発、Claude等）／人間編集者：** 自力で候補を探し、原典を調べ、調査中から見出し・日本語原稿・図表を作り、必要なら追加取材する。完成記事と研究原本を作る。読者向け本文の品質まで責任を持つ。
- **独立確認役：** 可能なら別のAI／人間が原典・数字・文章の意味を照合。確認できなければ未実施と記載。
- **Codex：** 完成原稿の原文を保全、個別/累積ZIPの受領・差分/重複/改訂、正式UIデータへの変換、非公開保存・PC/スマホ画面検査。本文の根拠のない補筆・再要約をしない。
- **オーナー：** 本番公開、デプロイ、課金などを決める。担当者は勝手に実行しない。

## 1. 全事例の冒頭で自分に聞く
この商売の**商品、買い手、支払者、購入理由、初売りの実際、集客と成長の方法、収益実績、現実に必要だった技能・人・お金**を、固有の事実で説明できるか。知名度・売上額・収集可能な項目数ではなく、読者の発見と原資料の豊富さを重視する。

## 2. 調査の順序（省略しない）
1. 既存社名・商品・ドメイン・改訂・未掲載原稿と、現にアクセスできる範囲で照合。
2. 候補を調べ、当事者の公式サイト/料金、創業者発言、当時の資料、公開決算、独立取材で価値と真偽を確認。抽象的な企業概要しかない候補は変更。
3. 一覧・タイトル・リード・7本文分類のうち有用な章の**仮原稿をすぐ書く**。読み手が「誰が何をどうしたか」を理解できるか確認。
4. 書きながら、欠けている初期の顧客の接点、営業・投稿の具体的内容、反応、価格、拡大の原因候補、数値の対象時点を**追加で調べる**。
5. 本文で使う情報と別に、費用・競合・背景・運営・発見・初期資源・顧客レビュー・出典・権利・未掲載素材を研究原本に残す。必ず17領域を見渡し、空欄を無理に埋めない。
6. 文章、表、年表、図を記事に最適な形にして全体を推敲。見出しは「問い」でなく事例固有の「答え」にする。
7. 主要主張と原典を突合し、売上/利益/取扱高、企業/商品、期間、創業者の発言と自分の解釈を区別。読みやすい常体・平易な日本語に直す。
8. **完成日本語原稿全文**・出典・研究/権利・有用なオリジナルSVG実体を納品し、可能なら実ZIP／Library保存と読み戻しを実施。記事品質と保存技術は別判定。

## 3. UIに書く記事の基本形
- 一覧の1行：何の商売・どんな特徴か。
- 詳細見出し：固有の売り方・成果。
- リード：商売の正体と読む価値を原則1〜2文。
- 代表数字：意味のあるものだけ。既存UI帯は最大4件。時点・通貨・測定対象を明示。
- **本文は（存在し掲載価値のあるものだけ）：概要／仕組み／お金／集客／運営／経緯／成功の理由**。順序は固定。最後に独立した**出典**。
- 章内の見出し・短文・箇条書き・番号付き手順・料金表・比較表・年表・独自図解は自由。内容に必要なものだけ選び、空章・ダミー表・図ノルマなし。
- 研究メモ／欠損／権利チェック／制作の弁解／意味のない「利益ではない」等は本文に出さず裏側へ。ただし指標の意味や重大な限定は隠さない。

## 4. 強制的に不合格とする例
- 調査先が3本あり、文章が「SNSで集客、顧客志向で成長」しか伝えない。
- 最初の客、調達・初売りの実像が重要なのに、近年の売上と創業日だけ詳しい。
- 実売上とGMV、資金調達と売上、2022年の料金と現在料金を混同。
- 主語が分からない直訳・意味不明な名詞連結、質問だけの小見出し、経緯と成功理由に同じ文の繰り返し。
- 他社製品画面を権利確認なく同梱、根拠のない成長矢印を描く。
- 検索・JSON・ZIP・保存・テストだけ完了して、**読者がそのまま読める記事が無い**。
- まだCodexへ渡っていないのに本番に出たと報告、非公開レビューだけで公開承認とみなす。
