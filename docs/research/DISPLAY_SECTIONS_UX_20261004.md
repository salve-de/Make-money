# MAKEMONEY 個別事例の表示設計: 25項目をどう見せるか

## 結論

25項目を調べることと、25個の同格の見出しを毎回読ませることは分けた方がよい。収集範囲は維持し、表示は「商売が分かる」「立ち上げと成長が追える」「収支と必要資源を判断できる」を中心に再編集する。

ただし、見出しを減らすこと自体が改善ではない。本文の意味の区切りが分からなくなれば、見出しが多い方が探しやすい。資料のある面白い経緯まで隠すと、読み応えと発見性を失う。科学的に決まった最適見出し数は、この調査では確認できなかった。

以下は研究から支えられる原則と、MAKEMONEYに適用する設計仮説を分けた提案。MAKEMONEYの実利用者で検証した結果ではない。

## 1. 研究から言えること

### 見出しの数ではなく、情報の探しやすさと内容の関連性を見る

Morkes & Nielsenの測定研究は51人・5条件の実験で、旅行サイトを使った。スキャンしやすい条件には、箇条書き、強調、短い区切りに加え、見出しの増加が含まれる。短文化条件は文章量を減らしたが、課題に必要な情報は残した。「見出しを減らす」「必要な情報も半分にする」の根拠にはならない。古いウェブ環境の小規模研究であり、有名な124%改善は複合指標の当該実験値で、現在の事例記事の改善率を予測しない。

一次実務実験: [Morkes & Nielsen, 1997](https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/)

NN/gの視線観察では、内容を具体的に表す見出しを手掛かりに本文を選んで読むパターンが確認されている。本文を短く切るだけでなく、何を読めるか分かる見出しが必要。「成功の秘訣」のような抽象語より、「最初の顧客は既存の仕事仲間だった」のように事実が伝わる表現を検討できる。後者の具体例は今回の設計提案であり、同社がこの文言を実験したわけではない。

一次実務調査の解説: [NN/g, Layer-Cake Pattern, 2019](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)

### 折りたたみは、長文を消す万能策ではない

NN/gは、読者が大半の区画を必要とする場合や連続した物語を読む場合、アコーディオンが操作を増やし、文脈を分断すると整理している。また、隠すことで内容の存在が分かりにくくなり、中身の薄いページにも見える。これは研究蓄積に基づく実務ガイドであり、「何項目で悪化する」という単一実験の閾値ではない。

一次実務研究機関のガイド: [NN/g, Accordions on Desktop, 2023](https://www.nngroup.com/articles/accordions-on-desktop/)

GOV.UKの現行設計ガイドも、全員が必要とする内容には使わず、まず折りたたまない内容で試すことを推奨する。実装時にはキーボード操作、見つけやすい開閉ラベル、ページ内検索なども必要となる。アコーディオン自体が常に悪いわけではない。

一次運用機関の設計・調査ガイド: [GOV.UK, Accordion](https://design-system.service.gov.uk/components/accordion/)

### 段階表示は、読む目的に合わせて分ける

Progressive disclosureの実務原則は、頻繁に必要なものを最初に、専門的・稀に必要なものを次に置くこと。次の層への入口には、何があるか分かる名称が必要。重要な部分を短くしたというだけでは、この条件を満たさない。

一次実務研究機関のガイド: [NN/g, Progressive Disclosure, 2006](https://www.nngroup.com/articles/progressive-disclosure/)

### 比較には共通の軸が役立つが、記事全体をデータ表にはしない

BaymardのEC比較テストでは、ページを行き来して属性を覚える負担が観察され、仕様重視のサイトの参加者の67%が比較機能を利用した。一方、モバイルでは利用が少なく、狭い画面で横並びの利点が失われた。これはEC商品選択の実務調査であり、事業事例の学習効果の直接証明ではない。

一次実務調査: [Baymard, Product Comparison UX, 2022](https://baymard.com/research-articles/provide-comparison-features)

MAKEMONEYへの仮説は「共通の短い要約枠は比較用、本文は個別の因果経緯を読むため」と役割を分けること。共通枠では同じラベル・単位・時点を使う。欠損項目は非表示とし、列をそろえる比較表だけ「—」にする。事例ごとの面白さまで同じ枠の長さに押し込めない。

参考となる実務整理: [NN/g, Comparison Tables, 2024](https://www.nngroup.com/articles/comparison-tables/)

### 出典は読者価値がある。ただし長い検証記録とは分けられる

Stanfordの研究まとめは、第三者の根拠や参照先を示して情報の正確さを確かめやすくすることを、信頼性を支える方法に挙げる。根拠には複数の研究と未査読資料を含み、「出典をこの位置に置けば何%改善する」という配置実験ではない。

研究機関による一次研究のまとめ: [Stanford Guidelines for Web Credibility, 2002](https://credibility.stanford.edu/guidelines/index.html)

したがって、出典を全部末尾に隔離するより、特に売上・利益・人数など誤読の影響が大きい情報の近くに、時点と情報の種類を短く示す案がよい。詳細な照合履歴は別層へ移せる。この配置は検証可能性を狙う設計仮説であり、上記研究が最適位置を証明したわけではない。

## 2. 情報を残す基準

「短いから良い」「細かいから悪い」ではなく、次のどれかを変えるかで判断する。

- 誰が、何のために、何にお金を払うか分かる
- 最初の顧客をどう得たか、読者が具体的な行動を説明できる
- 成長・失敗・方向転換について、何を変えてどうなったか分かる
- 売上と利益、必要資金・人数・時間・難しさの理解が正確になる
- 自分が検討するときの条件や制約を見つけられる
- 情報の根拠、時点、不確実さを正しく判断できる

この基準は編集用の仮説であり、科学的に検証された採点尺度ではない。

本文から外しやすいのは、欄を埋めるための一般論、隣の章の言い換え、結論を変えない細則の逐語説明、事実で裏付けられない成功要因の断定。出典や不確実さの表示には、読者が内容を判断するための価値がある。

ここでユーザーのいう「こちら都合」は、利用ツールの紹介をアフィリエイト収益につなげるなど、媒体側の収益上の利点を指す。読者価値と運営収益は両立しうるため、収益につながることだけでノイズと判定しない。たとえば、ツールによって一人で運営できたこと、初期費用が下がったこと、実際に使う場面が分かれば、読者にも価値がある。

表示の仮説としては、本文では確認できる用途・役割を説明し、その近くか詳細層に利用ツールへの導線を置く。選定・配置を紹介料の有無だけで決めず、紹介料が発生する関係を読者が分かるようにする。全事例に長いツール紹介欄を必須化したり、本文と無関係な商品推薦を混ぜたりすることは避ける。具体的な収益設計や広告表示の法的要件は、このUX調査の対象外。

## 3. 25項目の振り分け案

分類は固定の身分ではなく、初期値。事業を理解する決定的な材料がある項目は上位へ移す。

- ① 常時中心: 基本的に本文や冒頭の共通枠に出す
- ② 材料が強いときの章: その事例の重要な経緯として普通に本文表示する。折りたたみを意味しない
- ③ 詳細・出典層: 関心のある読者が明示的な入口から見られる形で保持
- ④ 統合・重複解消: 独立した必須章にしない。事実は適切な章へ統合し、根拠の薄い抽象解説は作らない

| 項目 | 初期配置 | 表示方法・例外 |
|---|---|---|
| 1. 見出し | ① | 何の商売か、どこが興味深いかが分かるタイトル。売上だけを煽らず、期間・時点を明示する |
| 2. 物語 | ① | 独立した「物語欄」より、出発点→行動→結果→転機を本文全体の流れにする |
| 3. 事業形 | ① | 誰に何をどう提供し、どこで課金する商売かを冒頭で説明 |
| 4. 料金 | ① | 購入単位と代表的な価格。全料金プランや変更履歴は③ |
| 5. 顧客 | ① | 買い手と利用者を区別し、具体的な利用場面を事業形・痛みと一体で説明 |
| 6. 痛み | ① | 購入理由や従来の代替手段の不便。抽象的な「課題解決」は避ける |
| 7. 初客 | ① | 相手、接点、提示したもの、決済までの経緯。確認できない項目は非表示にし、推測で埋めない。残る説明の解釈を変える条件は保持 |
| 8. 集客 | ① | 立ち上げ期と成長期を分け、実際に試した施策と確認できる反応を記述 |
| 9. 売上 | ① | 金額・期間・通貨・対象事業・時点・情報源の性質を一組で出す |
| 10. 費用 | ① | 利益判断に効く主な費用と人件費の扱い。細目は③、根拠のない費用欄は非表示。表示した利益・残額の解釈に必要な費用範囲は残す |
| 11. 手取り | ① | 純利益、営業利益、創業者報酬を混同しない。売上から安易に推計しない。根拠のない欄は非表示にし、掲載する金額の把握範囲は保持 |
| 12. 資金人数 | ① | 最初に必要だった資源と現在の運営規模を区別。人数だけでなく作業・稼働の負担が分かれば併記 |
| 13. 道具 | ③ | ツール一覧や実装詳細は補足。必須の資格・設備・技術や、参入費用を左右するものは①へ |
| 14. 依存 | ① | 特定顧客、プラットフォーム、仕入先、創業者本人など、収益継続や再現性を左右する重要な依存だけ短く示す |
| 15. 継続 | ② | リピートや解約防止の仕組みが確認できる場合。定額課金など商売自体の説明に必須なら①へ |
| 16. 前金 | ② | 在庫・仕入れ・資金繰りを可能にした事実なら重要章。通常の決済時点の説明だけなら事業形や③へ |
| 17. 紹介 | ② | 成長の主要経路なら集客の主役に。単なる紹介制度の存在だけなら③、集客と二重説明しない |
| 18. 大手死角 | ④ | 毎回独立章にすると後付けの市場解説になりやすい。具体的な供給不足や既存企業の制約の証拠があれば顧客・競合の説明へ |
| 19. 競合 | ② | 顧客が比較していた代替手段や選ばれた理由が分かる材料を出す。網羅的競合カタログは③ |
| 20. 年表 | ④ | 本文と同じ出来事を重ねない。最重要の時点は本文、比較に便利な短い流れは要約、完全年表は③ |
| 21. 勝因 | ④ | 集客・商品・転換の章で事実と結果を説明する。事例一件から因果を断定せず、創業者の見解ならそのように示す |
| 22. 現況 | ① | 現在も営業中か、規模・事業形が変わったか、いつ確認した情報かを見える位置へ |
| 23. 転換 | ② | 何を、なぜ、どう変え、何が起きたか分かるなら本文の中心に。全事例で形式的に作らない |
| 24. 失敗 | ② | やったこと・結果・対処が具体的なら強い材料。失敗談が確認できないことを成功だけだったことにしない |
| 25. 教訓 | ④ | 「顧客理解が大切」などの一般論は削る。事実から言える範囲や、真似する前に確認すべき条件を必要なら短く添える |

重要なのは①の各項目に独立見出しを割り当てないこと。「顧客・痛み・事業形・料金」は一つの商売の説明、「売上・費用・手取り」は一つの収支の説明として読める。

### 補足項目の扱い

- 経歴: 最初の顧客・専門性・資金・販路に結びつく経験なら本文。それ以外は略歴
- 顧客数: 売上の分母、単価、集中度、利用規模を理解するためなら収支や事業説明へ。無料会員・契約社・利用者を区別
- 規約・返品・配送: 費用、責任、粗利、供給能力、提供価値を変える要点は本文。条文や細則全文は詳細層
- 技術詳細: 一人で作れる条件、差別化、保守負担を左右すれば要点を本文。ライブラリや実装手順の羅列は詳細層
- 出典: 主要な主張には近くで根拠が分かる導線。全出典・補足照合は末尾または詳細層
- 未確認事項: 重要な判断を左右するものは該当箇所で短く示す。すべての未確認欄を独立した空の章にしない

## 4. 自然なページの構成例

次は試作の出発点であり、最適な6章という研究上の結論ではない。一本の短い記事なら統合でき、豊かな材料があれば章は増えてよい。

### 冒頭

- 何を売り、誰が買う商売かが伝わるタイトル
- その事例固有の面白い事実を短い導入で示す
- 比較用の共通枠: 何を売る／顧客・価格／売上と利益の判明範囲／立ち上げ資源と運営規模／現況と情報時点
- 長い記事には「この記事の内容」。本文へ飛ぶ目次は内容を隠さない

### 本文の見出し案

1. 何を、誰に売っているのか
2. 最初の一件はどう生まれたか
3. 売上が伸びたきっかけ
4. 売上から、いくら残るのか
5. 続けるための仕事と必要なもの
6. 今どうなっているか

各章は、実際の事実が伝わる事例別の見出しに書き換える。たとえば、確認できる場合に「知人への手作業の提供から始まった」「一度やめた広告を、対象を絞って再開した」など。抽象的な煽り文句ではなく、読みどころの内容を示す。

大きな方向転換、具体的な失敗、紹介で伸びた経緯などが豊かなら、3の前後に独立した章として展開する。すべての事例を同じ長さにしない。長くても読者の理解が進む具体的経緯は残す。

### 補足の入口

「補足」だけにせず、「使用ツールと技術構成」「料金の内訳と契約条件」「全出典・数字の確認方法」のように、中身を予測できる名称にする。多数の入れ子の開閉は避ける。全体を読む必要があるなら通常本文の方がよい。

数字の近くには、たとえば「月商○○／20XX年○月／創業者公表／利益は確認できず」のように、数値の解釈に必要な条件を出す。長い出典説明を読むまで売上と手取りの違いが分からない構造にはしない。

## 5. 提示された悪例への適用

以下は提供された問題点に基づく編集案で、各事例の事実の再検証を行った結果ではない。

### GoGoNano

乾燥24時間、再処理、返品規約を商品手順として長く並べても、誰が何のために買い、どう売れたかの理解が進まないなら、詳細層へ移す。

ただし、乾燥時間が用途や販売先を制限する、再処理が実際のリピート購買につながる、返品が利益を圧迫する、という事業上の関係が根拠から分かる場合は、その関係を短く本文に残す。再処理の必要性だけから継続収益があると推測しない。

### Kamero

注文枠の返還、決済の経路、細則は、主本文を占有させず運用の詳細へ。もしそれが貸倒れ防止、供給能力、先に入金を得られる構造などに関係するなら、その仕組みの要点を本文に残す。

初客・転機の資料が少ない場合、決済細則を増やして記事を厚く見せても不足は埋まらない。確認できた出来事を厚く書き、単なる欠損欄は非表示にする。残る説明を誤読させる重要な条件は省かない。未確認の初客物語を創作しない。

### Buffer

SQSなどの技術名やインフラ掃除は、一般の事業検討者にとっては詳細層が初期位置。保守負担、人数、費用、信頼性などの変化が事業上の転機だったという根拠があるなら、その変化を主語にして本文へ。技術名の存在だけでは成功要因を説明したことにならない。

## 6. 「少なくて薄い」の境界

最適な字数で線を引く根拠はない。仮の品質チェックは、読み終えた人が次を具体的に説明できるか。

- 誰に何を売り、なぜ買われるのか
- 最初の売上を得るために、実際に何をしたのか
- その後に何を変え、どう伸びた／伸びなかったのか
- 収支は何が分かり、どこからは分からないのか
- 始める・続けるために必要な資源と、無視できない制約は何か

「売上が大きい」「SNSで集客」「顧客に寄り添った」のような抽象語だけで、行動・前後・結果が説明できないなら、短くなくても薄い。逆に具体的な行動、変化、数字の条件が理解できるなら、補足を移しても薄いとは限らない。

読む満足は正答率だけでは測れない。驚き、意外な工夫、失敗からの変更など、その事例だけの発見が残っているかも見る。判断材料と読み物としての面白さの両方が必要。

## 7. 検証方法

### まず分けて検証する

表示の違いを調べる試験では、同じ事実を保持する。A案は25項目を同格表示、B案は統合された常時本文＋明示的な詳細層。情報を削る試験を同時に混ぜると、整理が効いたのか、材料の増減が効いたのか分からなくなる。

「もっと短いC案」も試すなら、Bとの違いを具体的に定義し、失われる情報が何かを記録する。薄さの境界を探すための実験条件であり、先に短文化を正解にしない。

### 利用場面

1. 自由に読む: 気になる事例を選び、普段どおり読む。何が読みたくなり、どこで興味が続かなくなるかを見る
2. 内容を説明する: 買い手、最初の顧客、成長の契機、収支、必要資源を自分の言葉で説明してもらう
3. 比較する: 自分の時間・資金・経験の条件を置き、二つの事例のどちらを詳しく調べたいか、事実に基づく理由を答えてもらう
4. 確かめる: 売上の時点と出典、利益が確認できるか、補足に必要な情報があるかを探してもらう

創業前と経験者、スマートフォンとデスクトップを分けて観察する。複数事例・複数形式の順序は釣り合うようにし、同じ記事を先に読んだ知識が別形式に有利に働かないようにする。

### 主な評価項目

- 必要情報にたどり着けたか、正しく理解できたか
- 売上を手取りと勘違いする、不明をゼロと扱う、相関を勝因と断定するなどの重大な誤読
- 興味深かった具体的事実、覚えている行動や転機
- 自分の検討に使えると思う点と、まだ足りない点
- 「読む価値がある」「読み応えがある」「探しやすい」の主観評価
- 詳細があることに気づいたか、必要な人が見つけられたか

滞在時間やスクロール率だけを成功指標にしない。滞在時間が長いのは難解だからかもしれず、短いのは必要情報がすぐ見つかったからかもしれない。補足の開封率が低いだけで不要とも判断できない。必要とする少数の読者にとっては決定的な場合がある。

初回は小規模な観察で問題を発見し、改善する。平均効果を主張する比較実験は、主評価指標と検出したい差を決め、必要人数を別途設計する。「5人で最適見出し数を確定」のような結論にはしない。

## 最終方針

収集は広く、本文は読者の疑問に沿って編集する。詳細は保持し、存在が分かる入口を付ける。資料の強い出来事にはしっかり紙幅を使い、同じ説明の反復や根拠の薄い一般論で量を足さない。25個の調査欄を25個の必須表示章に変換しない、というのが今回の提案の中心である。
