# 収集から画面までの流れと、画面の1文から事実へ辿る記録（設計）

2026-10-08 のオーナー指示を受けて、関門を軽くした設計です。指示は「収集の段階で絶対に正しいものが出るようにするのは必須ではない。なるべく最適に、UIに出すまでを簡単にしたい。出る内容が不適切なら整えて出してもよい」。

## 守る原則は1つ

**見る人に害のある嘘の数字を画面に出さない。** これを守るのは原文照合（#175）だけで、数字が出典の原文と合わない事実は画面に出さない。
それ以外の決まり（引用の長さ・文の書き方・辿れるか）は、自動で整えるか、測って記録するだけにする。事例ごと止めない。収集役への差し戻しを既定にしない。

## 流れ（1枚）

| 段 | 何をするか | 道具 | 止めるか |
|---|---|---|---|
| 1. 収集 | 調査記録を書く。事実の文・引用・出典URL・取得日、数字の種類と時点を付ける | Codex（`scripts/reader-case/collect-prompt.md`） | 止めない |
| 2. 取り込み＋整える | 直せる物は自動で整える（下の表）。整えられない項目だけを隠して `unconfirmedFacts` に残す | `add-entity-records.ts --from-research` | 止めない（項目だけ隠す） |
| 3. 原文照合 | 事実の数字と時点を、出典の原文と機械で照らす。合わない事実は画面に出さない | `source-check.ts`（#175） | **ここだけ止める（その事実だけ）** |
| 4. 画面の文を作る | 照合を通った事実から、一覧・概要・分析・成功の秘訣・章の文を作り、落ちた行は自動で直す | `display:build` | 止めない（直らない行だけ出さない。今のまま） |
| 5. 測る | 画面の各行が事実と引用まで辿れるか、元の事実と食い違うかを数えて記録し、警告として出す | `display:trace`（D2） | 止めない |
| 6. 公開 | 目録を作って出す | `catalog:prepare` | 本番の反映だけ人の許可 |

## 段2で自動で整える物

| 落ちた理由 | 整え方 | 整えられない時 |
|---|---|---|
| 文の数の一部が引用に無い（2026-10-07 の Rewardful の8件。料金の価格だけを引用し、月間取引額の上限が引用に無い） | 取得済みの出典の本文から、その数を含む短い一節（15語まで）を探し、追加の引用 `quotes` に足す | その事実だけ隠す |
| 引用が無い・短すぎる | 同じく出典の本文から、事実の数や固有名詞を含む一節を探して付ける | その事実だけ隠す |
| 取得日が無い | 同じ出典の取得日（`reaudit.sources[].checkedAt`）で補う（実装済み） | その事実だけ隠す |
| 文が読みにくい（程度の語・英語のまま） | その事実だけ隠し、件数を記録する。画面の文は段4で作り直すので、事実の文の書き方では止めない | 同左 |
| 同じ種類・同じ時点で数字が食い違う | 両方を隠す（嘘の数字を出さない原則なので、ここは整えない） | 同左 |

整えた事実も段3の原文照合を通る。足した引用が出典に無ければ、そこで落ちる。

## 辿る記録（D1・D2・D4、測るだけ）

2026-10-07 の実測（公開10件、main 9882c43c）では、一覧の文・概要・成功の秘訣・分析欄・数値の帯の179行は、すべて照合済みの引用まで辿れた。章は328行のうち、辿れる行が0行だった。

- 229行は、照合済みでない出典（本人ブログ・別のインタビュー・保存版など）を引いている。10件の章は、照合を通らずに `data/case-chapters.json` へ直接書かれた（6e8d3756）。
- 画面の層を作る道具も、AIが返した `factId` を出典URLに変えた時点で捨てている（`src/shared/display-build.ts` の `assembleDisplay`）。

| # | 決定 | 理由 |
|---|---|---|
| D1 | 章の行に `factId` と `factHash` を保存する（任意の欄として足すので、今のデータはそのまま読める） | 他の欄と同じ結び方。これが無いと段5で数えられない |
| D2 | `pnpm display:trace` で、画面に出る全行を `辿れる` / `根拠IDが無い` / `根拠が画面に無い` / `元の文が変わった` / `引用が無い` / `照合で不合格` に数え、`data/pipeline/display-trace/ledger.jsonl` に1回1行で残す。lint にも公開にも組み込まない | 測って記録するだけ（オーナー指示） |
| D4 | `display:trace --judge` で、辿れた行を作ったAIとは別のAIに渡し、元の事実との食い違いを判定する。**数字の食い違い**だけは、`display:build` の作り直しの対象に自動で足す（嘘の数字を出さない原則）。それ以外は記録だけ | 原則は1つだけにする |
| D5 | 章の作り直しは、整える工程として、照合を通った事実がある行だけを `display:build` で作り直す。外部の出典にしか無い行は残し、件数を段5で記録する | 公開データの更新は、申請・自動テスト・統合の通常の流れで行う |

## 取りやめたこと

- 辿れない行を画面で落とすこと（旧 D3 後半）と、件数の基準を0にすること（旧 D3）。
- 取り込みで落ちた項目を、既定で収集役へ差し戻すこと。指示書と回数は、`--return` を付けた時だけ使う。
- 価格と上限を分ける決まりを収集役に守らせること。収集の手順には「なるべく」として残し、守られなくても段2で整える。

## 実装の順番（#175 の統合後に、最新の main の上で、必要最小限だけ）

1. 段2: `applyNumberContract` の後に「整える」を足す。出典の本文は #175 の `data/source-cache` から読む。差し戻し（`returnToCollector`）は `--return` の時だけにする。試験の見本には Rewardful の8件と同じ形の事実を使う。
2. D1: 章の行の型（`src/shared/case-chapters.ts` の `ChapterRow` と、`display-build.ts` の `ChapterEntry`）に任意の `factId` と `factHash` を足す。`assembleDisplay` でこの2つを保存する。
3. D2: `src/shared/fact-trace.ts` に、画面の行の列挙と数え方を純関数で書く。読み込みと出力と台帳は `scripts/reader-case/trace-check.ts` に置く。
4. D4: `--judge` を足す。
5. D5: `display:build` で章を作り直す。画面の文の直し（#175・#178 の統合後に別の担当が行う）と同じファイルを触るので、その統合の後に最新の main を取り込んでから行う。
