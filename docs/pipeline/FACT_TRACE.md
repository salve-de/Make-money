# 画面の1文から元の事実へ辿る（設計メモ）

2026-10-07 夜のオーナー指示「UIに出す内容から、収集の段階まで、本当に問題なくできているのか」への設計。
**状態: 設計だけ。** 画面の層は別の申請（`feat/reader-clarity-20261007`）が触っているので、その統合後に実装する。

## 目的

画面に出る1文ごとに、元の事実（事実ID）→ 原文の引用 → 出典URL を機械で辿れるようにし、辿れない文・元と食い違う文を画面に出さない。

## 鎖（4つの輪）

| 輪 | 何を持つか | どこで作るか | 状態 |
|---|---|---|---|
| 1. 原文 → 事実 | 事実ごとの `quote`（原文どおり3〜15語）・`sourceUrl`・`checkedAt`、数字は `numberKind`・`asOf` も | 調査記録（`docs/research-record/README.md`）。取り込み `add-entity-records.ts --from-research` が、引用の無い事実を取り込まずに差し戻す | **入った（この申請）** |
| 2. 事実の合格 | 事実IDごとの原文照合の合否 | 原文照合 `scripts/reader-case/source-check.ts`（#175）の `data/source-check/state.json` | #175 で入る |
| 3. 事実 → 画面の文 | 画面の各文（一覧の文・概要・章・分析・成功の秘訣・根拠欄・数値）が、どの事実IDから作られたか（`basis: ["f3","m2"]`） | 画面の層の各ファイル（`data/list-lines.json` ほか）。作る道具（`pnpm display:build`）が書かせる | 未（reader-clarity の統合後） |
| 4. 言い換えの一致 | 画面の文と元の事実の、数字・時点・主体・何の数字かが一致しているか | 別のAI（作った側と別）が、事実と画面の文を並べて判定 | 未 |

## 輪3・4の決まり（実装する時の仕様）

1. 画面の文は、すべて `basis`（事実ID・数字IDの配列、1つ以上）を持つ。持てない文は「根拠なし」として画面に出さない。
2. `basis` の事実が、原文照合で今合格（state が PASS）でなければ出さない。元の事実の文が変われば（指紋が変われば）画面の文も出さない（今の `factHash` の仕組みを全欄に広げる）。
3. 数字を含む画面の文は、その数字が `basis` の事実か数字の欄にあること（円換算の概算を除く）。「年商」「月商」は、`basis` の数字の `numberKind` が `REVENUE` の時だけ。
4. 同じ数字（金額・人数）は、1事例の画面で1か所だけ（`CASE_TEXT_STANDARD.md` の重複禁止を、`basis` の数字IDで機械で数える）。
5. 別のAIの判定は、事実と画面の文を並べ、`一致／食い違い（数字・時点・主体・何の数字か・程度）` を返す。食い違いは画面の層の作り直しに回す（上限3回、その後は保留）。
6. 回ごとに、辿れない文の数・合格していない事実に結ぶ文の数・食い違いの数／画面の文の数を `data/source-check/ledger.jsonl` と同じ形で残す。

## 公開10件の画面で見つかった例（輪3・4で止めたい物）

- 「年商」の見出しに年商でない数字（直接の支払い489件の合計）。
- 同じ数字が1事例の画面に5か所前後。
- 文中に出どころの印（「（保存ページ）」「（インタビュー）」など）。
- 料金の欄に料金でない条件（無料試用にカードは要らない、など）。
- 同じ出典が章ごとに繰り返す。
- 意味の取れない文（「よく払い／ほぼ払わなかった」）。

## 取り込み側の差し込み口（もうある物）

- 事実の文の検査: `scripts/architecture/fact-text-checks/*.mjs`（既定の出力が `(text, fact) => string[]` の関数。空なら合格）。`add-entity-records.ts` の `loadFactTextChecks` が読み込み、落ちた事実を差し戻す。別の担当の「意味が取れるか」の検査は、ここに1ファイル置けばつながる。
- 差し戻し: `data/runner/instructions/collect-return/<名前>.md`（指示書）、`data/runner/collect-return-state.json`（項目ごとの回数。3回で保留）。
