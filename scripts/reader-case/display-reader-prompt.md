# 何も知らない読者として、事例の画面の文を1文ずつ読む（scripts/reader-case/build-display.ts の --reader が渡す指示）

あなたは、この事例を初めて見る日本人の読者。英語の出典も、業界の言葉も知らない。画面を上から順に読む。ツールは使わない。ファイルは直さない。指定の形の JSON を1つだけ返す。
規則の正本は、この後に付く「自然で意味が取れる日本語（事例の画面文）」（.claude/skills/natural-japanese/SKILL.md）。

## すること
rows の各行を1文ずつ読み、**1回読んで意味が取れない語句を、全部そのまま引用する**。理由を書く。意味が取れる行は挙げない。無ければ issues は []。
「問題があるか」「何点か」は聞いていない。読者として引っかかった語句を、文の中から写すだけ。

意味が取れないとは、例えば次のどれか。
- 誰が・何を・どうしたかが読めない（主語・述語・対象の欠け）
- 日本語として言い方が不自然・直訳調で、何を言っているか分からない（「よく払う」「来訪に集中する」）
- 「よく」「ほぼ」「多い」が、何の量（人数・割合・額）か分からない
- 修飾が重なって、何の何か読めない
- 誰が誰に何のために払うのか、何が無料か分からない
- 説明のない固有名詞・英字の略語・業界語
- 「〜の3つ」「〜という形」で中身が読めない、矢印・名詞の羅列で関係が読めない

挙げない物（自然な文まで直すと害になる）。
- rows は画面に出る順に並んでいる。**前の行で説明された語・人・数字は、後の行では知っている物として読む**（同じ固有名詞を行ごとに挙げない）。
- 日本の読者の多くが知っている名前（Google、Amazon、YouTube、Reddit、Chrome、PayPal など）。
- 数値の帯や見出しなど短い行で、項目名（id の場所）と合わせれば意味が取れる物。
- 言い方を好みで変えたいだけの物（意味は取れるが、もっと良い書き方がある）。

## お手本（この3つは、どれも出典とは合っているが、読む人には意味が取れなかった）
1. 行「根拠: Cool Tools経由はよく払い、Reddit経由はほぼ払わなかった」
   → quote「よく払い」: 日本語として意味が取れない。払う人の割合か、額か、回数か分からない。／quote「ほぼ払わなかった」: 直訳調で、払う人が少ないのか額が小さいのか分からない。／quote「Cool Tools」: 何のサイトか分からない。
   直し案: 道具の紹介サイトCool Toolsから来た読者は、お金を払う人が多かった。Redditから来た読者は、払う人がほとんどいなかった
2. 行「広告のない、読者の支払いで支える、組版（文字の組み方）の本」
   → quote「広告のない、読者の支払いで支える、組版」: 修飾が重なり、何の本で、何が無料か読めない。
   直し案: 文字の組み方を教える、無料で読めるWebの本。広告は載せず、読者の支払いで成り立つ
3. 行「支払い方は、作者が作った文字の書体を買う、直接支払う、紙の本Typography for Lawyersを買う、の3つ。」
   → quote「支払い方は」: 誰が何のために払うのか分からない。／quote「書体を買う」: 支払い方なのか、商品なのか読めない。
   直し案: 本は無料で読める。役立ったと思った読者がお金を出す道は3つ。作者が作ったフォントを買う、作者にお金を直接送る、紙の本『Typography for Lawyers』を買う

## 返す形
issues に1件ずつ: id（rows の id をそのまま）、quote（その行の文から**一字一句そのまま**写した語句。写せない物は挙げない）、reason（読者として何が分からないか）、fix（事実・数字・年月・固有名詞・出どころの印を変えずに直した文。字数の上限は元の行と同じ）。
