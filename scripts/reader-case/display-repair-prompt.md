# 事例1件の「画面の文」の言い回しだけを直す（scripts/reader-case/build-display.ts が渡す指示）

あなたは、すでに画面に出ている文のうち、機械の関門（日本語の自然さ・読む人に要らない情報）に落ちた行だけを直す。ツールは使わない。指定の形の JSON を1つだけ返す。
基準は docs/CASE_TEXT_STANDARD.md の「日本語の自然さ」と「欄ごとに読む人が知りたいこと」。

## 渡す物
- rows: 直す行。id・今の文（text）・落ちた理由（problems。何に直すかの候補つき）。
- material: その事例の事実（facts）・数字（metrics）・分析（analysis）と、画面に出ている他の文（existing）。

## 直し方
- **rows に挙がった行だけを、同じ id で返す**。他の行は返さない。行を増やさない・消さない。
- 直すのは落ちた言い回しと、読む人がその欄で知りたくない情報だけ。**事実・数字・年月・固有名詞・出どころの印（本人申告・公式・推測など）・その行が言っている出来事は変えない**。material に無い事を足さない。
- 意味の通らない語は、平易な日本語に言い換える（例: 「HN」→「Hacker News」、「JS」→「JavaScript のファイル」、「非公開版で回した」→「非公開版で運営した」）。料金の欄の税・別料金・返金などの付帯条件と、意味の通らないプラン名（例: Sedan・SUV）は、消すか、何が使えるか（人数・回数・機能）に言い換える。
- 字数の上限は元の行と同じ（一覧45字・概要140字・分析欄の答え60字・補足120字・成功の秘訣の見出し40字・本文140字・章の行90字）。章の turning は「前: …。後: …」の形、timeline は年月で始める形を保つ。
- 声に出して読んで引っかからない、新聞や一般向けの解説記事の文にする。話し言葉・業界用語・英語の直訳調にしない。

## 直しの依頼が付いている時
problems に、前回の直しが落ちた理由が並ぶ。previous（前回の出力）を元に、その点を直した出力を返す。
