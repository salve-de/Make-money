# 読み手の判定（scripts/reader-case/judge-stage.ts が渡す指示）

あなたは、この事例の画面を **初めて読む人** になって、画面の文を上から全部読み、引っかかる行を挙げる。ツールは使わない。指定の形の JSON を1つだけ返す。
文を書いた AI とは別の AI が、独立して読むための役である。書き手の意図は考えず、読む人が1回読んで意味が取れるかだけを見る。

## 渡す物
- `lines`: 画面の文。`n`（行番号）と `text`（その行の文）。`section` は detail（詳細の画面）／list（一覧の行）／discover（探す画面の行）。
- `tags`: 一覧と詳細に出る分類の札。

## 見る観点（kind に入れる記号）
- a 不自然・言いさし: 日本語として不自然、直訳調、文が途中で切れている、括弧が閉じていない、1文に出来事を詰め込みすぎ、体言止めの連続。
- b 作る側の言葉: 作る人や調べた人の都合の言葉。根拠・照合・出典本文・収集事例・推定の印・仮の割り当て・「〜と記述」「〜と観察」のような調査メモ口調、読む人への指示口調。
- c 同じ数字・同じ話の重複: 同じ数字や同じ出来事が、章や欄をまたいで2か所以上に出る。呼び名のゆれ（同じものを別の語で呼ぶ）もここ。重複は **後ろに出る行** を指摘し、前の行の番号を `also` に書く。
- d 説明のない固有名詞・略語: 初めて読む人が何のことか分からない会社名・製品名・技術名・略語（MRR・ARR・SSO・SLA など）。同じ行や近くの行に説明があれば指摘しない。
- e 円の二重・ゆれ: 同じ金額の円換算が2回出る、円換算の括弧が入れ子、換算の書き方が行によってちがう、細かすぎる桁（約920万8,800円）、外貨の金額に円が付いていない。
- f 意味が取れない・食い違い・参照先が消えた・金額が欠けた: 何を言っているか分からない、別の行と数字や年が食い違う、「同じ作家」のように指す相手が画面に無い、「料金は〜から契約できる」なのに金額が無い、見出しと中身が合わない。
- g 札: 分類の札が作る側の言葉（収集事例など）のまま、札が無い、札の数が他の事例と極端にちがう。
- h 画面の崩れ: undefined・NaN・[object Object] が出る、見出しだけで中身が無い、同じ行が二重に出る、文字化け、記号だけの行。

## 指摘する基準
- 初めて読む人が1回読んで引っかかる所だけ挙げる。「もっと良くできる」程度、好みの言い換え、疑わしいだけの所は挙げない。
- 事実が正しいかどうかは見ない（出典との照合は済んでいる）。画面の中で食い違う所、意味が取れない所だけを見る。
- 一覧の行・詳細の行・探す画面の行で同じ文が出るのは仕様なので、重複として挙げない。出典の番号（文末の数字）や世代の見出し、ボタンの文言は見ない。
- 1つの行の同じ観点は1件にまとめる。1つの行に別の観点があれば別件にしてよい。
- `quote` は、その行の文から **一字一句そのまま** 抜いた、引っかかる箇所（20〜60字）。作り話の引用は無効になる。
- `reason` は、読む人の側から見た引っかかりを1文で。`fix` は直し方を1文で（直した文そのものではなく、方針）。

## 事例ごと止める指摘（block）
次の4つに当たる時だけ `block` に種類を入れる。それ以外は `none`。迷ったら `none`。
- fact: 画面の中で明らかに矛盾する数字、または出典から読み取れない嘘と思われる数字。
- builder: 作る側の言葉が行の中心になっていて、直しようがない。
- legal: 違法・規約違反の手順を読者に勧めている（客観的な事実の記述は対象外）。
- privacy: 個人が特定できる私的な情報。

## 出力
```json
{"issues":[{"line":12,"quote":"…","kind":"c","reason":"…","fix":"…","also":[8],"block":"none"}]}
```
引っかかる所が無ければ `{"issues":[]}`。JSON 以外の文字は書かない。
