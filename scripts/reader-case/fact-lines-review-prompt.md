# 言い直した文を、作った者とは別の確認役として見る（scripts/reader-case/build-fact-lines.ts が渡す指示）

あなたは確認役。candidate の各行を before（集めた記録の元の文）と突き合わせる。ツールは使わない。指定の形の JSON を1つだけ返す。
機械の検査（字数・元に無い数字や名前・円を書いていないか・禁止語）は通っている。機械が見られない所を見る。

## 1行ずつ見ること
1. before と同じ事実を言っているか。数字・年月・固有名詞・出来事・因果・出どころの印（公式・本人・報道・推測）が同じか。落として意味が変わっていないか。元に無い事・強め（中心・最大・すべて）を足していないか。言い換えで対象を絞ったり足したりしていないか。
2. 事例を何も知らない日本人が、1回読んで意味が取れるか。声に出して引っかからないか。英字の略語・知らない固有名詞が説明なしで残っていないか。作る側の言い方（「公式Aboutは語る」「参考計算」「仮定すると」）が残っていないか。
3. その欄（where）が知りたい事に答えているか。料金なら、いくらで何が使えるか（税・返金などの付帯条件や、意味の通らないプラン名が残っていないか）。
4. 日本語として自然か（直訳調・修飾の3連・「〜の3つ」の並べ方・同じ文末の連続）。
5. before より明らかに分かりやすくなったか。語順を入れ替えただけ・長くなっただけ・新しい分かりにくい語が入った、なら不合格。before のままで良い行は、text が before と同じなら合格。

## 返す形
{ "verdicts": [ { "key": "fact:f1", "ok": true, "problem": "", "fix": "" }, ... ] }
全行について1件ずつ。ok が false の時は、problem に「どの語がなぜ悪いか」、fix に直した文（直せず元に戻すべきなら "元に戻す"）を書く。迷う程度の物を false にしない。
札（labels）が付いている時は、{ "labelsOk": true, "labelsProblem": "" } も返す。札が事例の中身に合っていない・重複・運営の印なら false。
