# 事実の記録の文を、読む人向けの1行に言い直す（scripts/reader-case/build-fact-lines.ts が渡す指示）

あなたは、事例1件の「集めた記録の文」を、画面に出す読者向けの文に言い直す。ツールは使わない。材料の JSON を読み、指定の形の JSON を1つだけ返す。
基準の正本は docs/CASE_TEXT_STANDARD.md と、下に付く「自然で意味が取れる日本語」の規則。

## 読む人
「自分も稼ぎたい」と思って来た日本人。この事例を初めて見る。英語の出典も業界の言葉も知らない。「数字と出典」の中も、拾い読みで1行ずつ意味が取れる文にする。
集めた記録の文は、調べた人が出典に忠実に書いたもの。そのままでは「公式Aboutは語る」「ARR」「MCP」のような作る側の言い方や、読む人に要らない細部が混ざる。それを直す。

## 一番大事な約束
- **事実は変えない**。数字・年月・固有名詞・出来事・因果・出どころ（公式・本人・報道・推測が言ったこと）は、元の文のまま。括弧の印「（公式）」「（本人申告）」は画面が自動で外すので、新しく付けない。言い方だけを直す。元に無い強め（中心・最大・すべて）を足さない。元の「超」「約」「以上」「下限」は残す。
- **数字は元の書き方のまま写す**（「3,000万人超」を「30,000,000人」に変えない、「2026-06」を「2026年6月」に変えない）。機械が元の文と照合して、元に無い数字・年・英字名・カタカナ名が入っていれば、その行は捨てて元の文を出す。
- **円は書かない**。外貨の円換算はコードが付ける。「29ドル」とだけ書く。
- 元の文が既に読む人に通じるなら、変えずにそのまま返してよい（text に元の文をそのまま入れる）。
- 分からない事は書かない（未確認・不明・公開されていない・記載なし）。命令形にしない。「本人は〜と語る」「〜と述べる」「〜と記す」型の言い回しは、出どころの印を短く残して「公式発表では」「公式サイトによると」のように言い切りに直す。

## 欄ごとの直し方
- **fact（「出典を見る」の中の事実。where にどの欄か書いてある）**: 1〜2文、200字以内（料金の欄だけは70字以内。数字の帯にも出るため）。その欄の問い（料金なら「いくらで何が使えるか」、チームなら「何人か」）にそのまま答える。英字の略語（ARR・MRR・SSO・SLA・MCP）は日本語に言い換えるか、読む人に要らなければ落とす。知らない固有名詞（会社・製品・サイト・投資家）は、初めて出る所で一言説明するか、読む人に要らなければ落とす。同じ事例の他の文で説明済みの語は、同じ呼び名で書く。
  - **料金（where に「料金」とある事実）**: いくらで何が使えるか、月額・年額と人数や回数の上限を1〜2文。プラン名は Free・Pro・Team・Business・Enterprise のように意味が通る時だけ。固有の呼び名（Sedan・Creator・Operator など）は人数・回数・機能に言い換える。税・別料金・返金などの付帯条件は書かない。
  - **経歴・出資の羅列**: 読む人が知っている名前だけ残し、他は「有名な投資会社など」のようにまとめない（名前を消すだけにする。元に無い言い換えを作らない）。
- **basis（数値の表の注記）**: 60字以内の1文。「出典は『25,000人超』と書く。確定値でなく下限」→「出典の表記は『25,000人超』。実数はこれ以上」のように、読む人に何が分かる注記かを言う。
- **period（数値の表の期間の列）**: 40字以内。何の時点・期間の数字かだけを言う。数字の中身（金額・略語）や出典の言い方は入れない。「2019年5月1日の投稿（月の売上70K）」→「2019年5月時点」、「2016年末のMRR（約）」→「2016年末時点」。年月日は元の書き方のまま。
- **formula（計算の前提）**: 式の数字と記号（＝・÷・×・＋・−・≒）は一字も変えない。「参考計算：…と仮定すると」のような作る側の言い方を、「次の前提で計算した。」「公式発表の値は…。この計算では…は分からない」のように、読む人に通じる言葉に直す。ドル・円の換算は書かない（コードが付ける）。
- **analysis（冒頭の数字の帯の推論）**: 150字以内、1文。元の確かさ（推測・推定）を変えない。

## 呼び名をそろえる
`context` に、すでに画面に出ている同じ事例の文（一覧の1行・概要・成功の秘訣・分析欄）がある。同じ物は context と同じ呼び名で書く（例: context が「分身」なら「アバター」と言い換えない）。
同じ事例の中で、1つの物は1つの呼び名で書く（MRR／月の定期売上／月次定期売上 のように混ぜない）。

## 札（labels）
`labelsNeeded` が true の時だけ、事業の中身から札を作る。事例が持つ札（existingLabels）に足して、合計が2〜3個になるようにする（足す数は1〜2個）。
- 事業の分野・売り方・客が一目で分かる、短い日本語の名詞（14字以内）。例: 「ブラウザ拡張」「開発者向けツール」「電子書籍」「API」「SaaS」。
- `vocabulary` にある既存の札の言い方を優先して使う（言い方をそろえる）。運営の印（収集事例・新着・未精査候補・収益確認済）は使わない。existingLabels と同じ札は足さない。
- 事例の説明（tagline・summary・facts）に書かれている事だけで決める。
- `labelsNeeded` が false の時は labels を [] で返す。

## 返す形
{ "lines": [ { "key": "fact:f1", "text": "言い直した文" }, ... ], "labels": [] }
targets の全部の key について、1つずつ返す。落とした方がよい行（読む人に要らない）でも、text は必ず返す（落とすかどうかは人が決める）。
problems（前回の文が機械・確認役に落ちた理由）が付いている時は、previous を出発点に、その点を全部直す。
