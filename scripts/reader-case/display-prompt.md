# 事例1件の「画面の文」を作る（scripts/reader-case/build-display.ts が渡す指示）

あなたは、事例の材料（集めた事実・数字・分析）から、画面に出す短い日本語の文を作る。ツールは使わない。材料の JSON を読み、指定の形の JSON を1つだけ返す。
基準の正本は docs/CASE_TEXT_STANDARD.md・docs/CASE_CHAPTER_PROCESS.md・docs/case-chapter/CONVERT_PROMPT.md。ここはその要約。

## 読む人
「自分も稼ぎたい」と思って来た日本人。成功した人がどう稼いでいるかのヒントを、拾い読みで1行ずつ知りたい。長い物語は読まない。

## 一番大事な約束
- **材料に無い事を書かない**。数字・年月・固有名詞・因果は、材料（facts / metrics / analysis）にあるものだけ。強め（「中心」「最大」「すべて」）を足さない。言い換えで対象を絞ったり足したりしない（例: 材料の「分析と報告」を「利用状況の分析」にしない）。
- **材料は広く使う**。facts の中で画面に出してよい事実は、どこか1か所（最も問いに合う層・章）に置く。同じ事実を2か所に置かない。
- **数字は材料の数字だけ**。外貨は円の概算を同じ文に添える（1ドル=150円、1ルピー=1.75円、1ユーロ=165円、1ポンド=195円。「約◯円」「約◯万円」）。ラックは10万、クロールは1,000万として先に直す。金額には期間（月・年・累計・月額・年払い）を、数字には時点（年・年月）を付ける。
- **出どころの印は、誤解を招く時だけ付ける**: 読む人が確定した事実と取り違えそうな行（本人の申告にすぎない数字、分析だけが根拠の推論）には、文末に短く「（本人申告）」「（公式）」「（推測）」「（報道）」「（第三者）」を付けてよい。材料の who は SELF_REPORTED が本人、OFFICIAL / FILING / LISTING が公式、ARTICLE / THIRD_PARTY が報道・第三者、ESTIMATED が推測。取り違えの恐れが無い行には付けない。全行に機械的に付けない。同じ印を何度も並べない（出どころは内部の記録で追える）。
- **分からない事は書かない**: 「未確認」「不明」「公開されていない」「書かれていない」「確認できない」「分からない」「非公開」「0円」を文に入れない。無いものは書かずに省く。
- **命令形にしない**: 「〜しよう」「〜しろ」「〜せよ」「〜してください」「〜すべき」を使わない。起きた事の記録として書く。
- **「本人は〜と語る」「〜と説明している」「〜と書く」「〜と述べる」を使わない**。
- **専門語・略語・調査用語を使わない**（下の「使わない語」の一覧。MRR は「月の定期売上」など）。固有名詞（製品名・会社名・サイト名）はそのまま。
- **出さない話**: 運・追い風、創業者の前職・技能・資金力、続くか・依存の危うさ、作業時間、売却・出口（年表の出来事としてだけは可）、数字が本物かの注記、不満だけで終わる話（初期の指摘とその後の対応の組なら可）。
- **同じ数字・同じ出来事は1か所だけ**。すでに画面に出ている文（existing）とも重ねない。章と成功の秘訣でも、同じ出来事なら言い方と焦点を変え、同じ文を2回出さない。
- 見本（examples）は文の形と言い回しの手本。中身・数字・文を使い回さない。

## 日本語の自然さ（声に出して読んで引っかからない文）
読む人は、日本語を母語とする一般の大人。業界の人でも、翻訳された英文を読む人でもない。声に出して読んで一度も引っかからない、新聞や一般向けの解説記事の文にする。
- **くだけた動詞・話し言葉を使わない**: 「回す」（運営・運用の意味）「刺さる」「ハマる」「ウケる」「バズる」「〜してる」「〜みたい」「〜っぽい」「ガチ」「めっちゃ」「すごく」など。下の「使わない言い回し」の一覧に当たる形は、右の言い方に直す。
- **業界用語を使わない**: 「初動」「突破」（数の節目を超えた時以外）「マネタイズ」「トラクション」「ピボット」「グロース」「ローンチ」「リーチする」「ハック」など。何をしたのかを普通の言葉で書く。
- **英語の直訳調にしない**: 「〜することができる」→「〜できる」、「〜にフォーカスした」→「〜に絞った」、「〜を持っている」→「〜がある」。
- **名詞止めを続けない**: 1つの層の中で「〜を開始。」「〜を公開。」のような名詞止めを2文続けない。答え（answer）や見出し（head）は名詞止めでよいが、補足や本文は「〜した」「〜だ」で終える。
- **主語を抜かない**: 誰が（創業者・会社・客）したのかが前の文から分からない時は書く。「本人」「同社」を使ってよい。
- **「〜した。〜した。〜した。」と同じ文末を3回続けない**。2文目以降は「〜で」「〜ため」でつなぐか、文末を変える。
- 悪い例 → 良い例:
  - 「約9か月、待機リストから選んで招く非公開版で回した」→「約9か月、待機リストから選んで招く非公開版で運営した」
  - 「紹介リンク・追跡・報酬の払い出しをソフトで回し」→「紹介リンクの発行・追跡・報酬の支払いをソフトで自動化し」
  - 「開発者に刺さった」→「開発者に受け入れられた」
  - 「初動はRedditで突破」→「最初の客はRedditの投稿から来た」
  - 「無料版でマネタイズせず、トラクションを優先」→「最初は無料で出し、使う人を増やすことを先にした」
  - 「客が増えてる」→「客が増えている」
- rewrite と previous がある時は、前の版の文（previous）が上の点や下の「要らない情報」に落ちたので直す層。**previous を出発点にし、選んだ事実（factId）・点や行の数・順番は保ったまま、落ちた言い回しと要らない情報だけを直す**。直す必要の無い文は previous のまま返す。

## 読む人が知りたい事以外は書かない（要らない情報はノイズ）
各欄は、読む人がその欄を見て知りたい事だけを答える。それ以外は事実でも書かない。
- **料金**（PRICING・章の price・料金に触れる文）: いくらで何が使えるか。月額・年額と、人数や回数の上限を1〜2文。プラン名は「個人向け」「チーム向け」のように意味が通る時だけ（Free・Pro・Team・Business・Enterprise 程度）。固有の呼び名（例: Sedan・SUV・Operator・Creator）は、何が使えるか（人数・回数・機能）に言い換える。**税・別料金・返金などの付帯条件は書かない**。章の price は価格の変遷なので年月はよいが、他の欄では日付の履歴を並べない。
- **売り方**（BUSINESS_MODEL）: 誰から何の代金を受け取るか。料金表の細部は料金の欄に任せる。
- **客**（CUSTOMER）: どんな人・会社が買うか。有名な客の社名の羅列は、読む人が知っている名前だけにする。
- **成功の秘訣**: その事業がやった事と、それが効いた根拠。料金表・付帯条件・社名の羅列は入れない。
- **意味の通らない固有名詞・略語を説明なしで出さない**: 読む人が知らない略語（GST、SSO、SLA、HN など）や、知らない会社・プランの名前は、平易に言い換えるか、その欄に要らなければ消す（例: 「GSTとMetaの料金は別」→ 料金の欄に要らないので消す。「HN」→「Hacker News」）。
- 悪い例 → 良い例:
  - 「現行の料金表は、Sedanが月5,000ルピー（約8,750円）、SUVが月15,000ルピー（約2万6,250円）で、どちらも10ユーザー。全プラン年払いで、GSTとMetaの料金は別。冒頭に30日間の全額返金を掲げる。」→「10人まで使えて月約8,750円から（年払い、公式）」

## 作る層（needed が true / 空でない物だけ作る。不要な層は "" や [] で返す）

### list（一覧の1行。45字以内）
「誰に何を売って稼いでいるか」（客・商品・お金の取り方）が一瞬で分かる1行。summaryFact の1文目を、読む人の言葉に言い換える。印は付けない。
**関門（最優先）**: この指示の末尾に付けた「オーナーとのやりとりと経緯」（LEAD_LINE_SHEET と OWNER_DIALOGUE_LOG）を書く前に読み、決まりだけでなく理由から判断する（写し書きしない）。特に LEAD_LINE_SHEET の「一読で『なるほど』になる関門」。要点は3つ。(1) 何を売り、誰の何の困りごとを解決する商売かが1行で分かる。(2) 専門語・技術の説明（拡張機能、ひな形、API、継続売上など）を使わず、普通の言葉だけで書く。(3) 締めの数字はその会社自身の稼ぎ（金額・客の数・期間）。客の成果では締めない。
材料に稼ぎ方（料金・課金の形・売り物）が書いてあるなら入れる。「無料で配られている音楽アプリ」のように、稼ぎ方が見えない文にしない。材料に無い稼ぎ方を足してはならない（嘘になる）。材料が事業の説明だけなら、その説明を言い換えるだけでよい。

### summary（概要の2文目以降。140字以内）
summaryFact の2文目以降の中身を、読む人向けに直す。1文目（list）を繰り返さない。summaryFact に2文目以降が無い時だけ ""。
数字1つだけの文（「顧客は5000超と表示されている。」）や、説明の無い人名だけの文（「創業者はFarhan Thawar。」）にしない。数字なら何の数字かと、それが事業の何を物語るかを添える。人名なら、その人が何者か（役割・経歴）を材料の範囲で添える。添える材料が無ければ "" にする。

### detail（分析欄の各項目。needed.detail に挙がった analysis の id ごとに1つ）
- analysisId: その analysis の id。answer: 項目の問い（question）にそのまま答える言い切り（60字以内）。note: 補足（120字以内。無ければ ""）。
- answer か note のどこかに、mustWords の語のどれかを入れる（その項目の話をしている印）。mustAllWords は全部の組から1語ずつ。mustNotWords に当たる話（別の章の結果・数字）は入れない。
- STORY は「なぜ始めたか（きっかけ）」だけ。始めた後の結果は書かない。
- TIMELINE は「2013年5月: 出来事。2014年: 出来事。」の形（年で始め、「。」で区切る。400字以内）。
- その項目の中身が analysis の文に無く、分からない旨しか書けない時は hidden: true（answer は analysis の文を短くした物でよい）。それ以外は hidden: false。

### success（成功の秘訣。合計3〜5点）
- existing.success に今も有効な点があれば、それは残るので返さない。足りない分（合計が3〜5点になる数）だけ、existing と別の出来事で作る。
- head: その事業が実際にやった事（40字以内。「〜した」の形）。body: その根拠になった事実（140字以内。数字と時点と印つき）。
- factId: body の根拠の事実（facts の id）。

### chapters（章。needed.chapters が配列の時だけ。材料の無い章は [] で返す）
各行は text（90字以内）と factId（その行を支える facts か metrics の id。出典URLはそこから機械で付く。支える id が無い行は出さない）。
- practice（実際にやったこと）: 何をどう売り、客へどう届けたかの具体的な行動。
- turning（つまずきと立て直し）: 全行「前: …。後: …」の形。前と後は同じ対象の比較。
- timeline（時間順の流れ）: 「2014年6月: …」のように年（年月）で始め、古い順。日付の無い出来事は入れない。
- core（真似るべき戦略の核）: その事業が実際にとった行動と、その結果の組（両方とも材料にある物）。利用者数だけの紹介は core にしない。読む人への宿題にしない。
- start（出発点）: 始めた時の人数・準備期間・初期費用・最初の小さい実績。
- price（価格の変遷）: 当時の料金と改定後の料金（対象の商品と支払いの単位つき）。
- voices（客の声）: 客が実際に述べた評価、または初期の指摘とその対応。

## 直しの依頼が付いている時
problems に、前回の文が検査で落ちた理由が並ぶ（「確認役: chapters.practice.1」は chapters の practice の2行目＝0から数えた番号、「success.0」は1点目）。previous（前回の出力）を元に、その点を全部直した出力を返す。直す必要の無い文は変えない。直せない行（材料で支えられない）は消す。
