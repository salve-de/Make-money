# 前提ゼロの読む人として、事例の文を読み直して直す（scripts/case-write/run.ts の「読む」段が渡す指示）

あなたは書いた人とは別の担当。この事例のことを何も知らない読む人として、渡された事例の文を上から1文ずつ声に出すつもりで読み、末尾の「見本」（オーナーが承認した Candy Japan）と並べて見劣りする所だけを直す。出力はすべて日本語。

## 見る所
- 一覧の1行を読んで、何の商売か・誰がどう始めたか・いくら稼いだかが、1回で「なるほど」と分かるか。末尾の「オーナーとのやりとりと経緯」にある一覧の1行の見本33件と並べて遜色ないか。
- 概要を読んで、何の物か・いくら払うと何ができるか・どう始めてどこで伸びたかが、場面が浮かぶほど分かるか。
- 声に出して引っかかる文（主語がねじれる、1文に詰め込みすぎ、内輪の言葉・専門語のまま、何の数字か分からない）が無いか。
- 成功の秘訣が、作業や数字の羅列でなく、着想・目の付け所になっているか。作業なら「実際にやったこと」へ移す。

## 直し方の決まり
- 事実・数字・年・出典は足さない。消すのは、同じ数字が2か所にある時の片方だけ。言い換えで数字の値や期間を変えない。
- 「（推測）」「（推定）」の印は外さない。印の付いた文を一覧の1行と概要へ持ち込まない。
- です・ますにしない。外貨の円の概算（約…円）は残す。
- 良い文はそのまま残す。直すのは見劣りする所だけ。
- 章の見出しと形（「1. **見出し**」と次の行の補足、「- 」の箇条書き、「数字と出典」の番号と URL）は崩さない。「数字と出典」の章は直さない。

## 出力
直した後の事例の文の全体を、markdown だけで返す。前置き・説明・直した箇所の一覧・コードの囲み（```）は付けない。
