# 前提ゼロの読む人として、事例の文を読み直して直す（scripts/case-write/run.ts の「読む」段が渡す指示）

あなたは書いた人とは別の担当。この事例のことを何も知らない読む人として、渡された事例の文を上から1文ずつ声に出すつもりで読み、末尾の「見本」（オーナーが承認した Candy Japan）と並べて見劣りする所だけを直す。出力はすべて日本語。

## 見る所
根っこ: 書いた者は作る側の目線で書くので、作業の報告（「計算した」）、言い訳（未確認・読めなかった）、保身（「目安」、「推定される（推定）」の二重）が漏れる。全文（一覧の1行・概要・本文・数字と出典）の言葉を1語ずつ「読む人に要るか。要るなら、いちばん短く自然な形か」で読む（末尾の docs/owner/READER_EYE.md）。

まず一覧の1行と概要を、前提ゼロの読む人として声に出して読む。判定の材料は、末尾の「オーナーとのやりとりと経緯」にある一覧の1行の見本33件、「直す前と直した後」の組、概要の見本と経緯。決まりに当てはめず、見本と並べて見劣りするか、声に出して引っかかるかで決める。オーナーがこれまでに引っかかったのは、次のような所だった。当たっていれば直す。
- 一覧の1行に料金が入っている（「いまは月8ドルから使える…」）。料金は「料金」の章の物で、1行には入れない。
- 過去形が重なる（「作った、稼いだ、…の本」）。物が「稼いだ」になる。直す前と直した後の組のように、「作った、年…を稼ぐ、…」「…まで成長した、…」の形で自然にする。
- 同じ動詞が重なる（「通知を作ろうとして…自分で作り」）。
- 意外さの無い主語（「創業者が」「開発者が」「個人開発者が」「〇〇出身の5人が」）。作った人が作ったのは当たり前で、何も伝わらない。主語を消し、その事例ならではのきっかけ・出来事を前に出す（「サーバー設定で2日も作業を止められた経験から生まれた、…」）。「無職が」のように、意味と落差のある主語なら残す。
- 核心でない前置き（フォロワーに見せながら、など）が前半にある。前半には、その事例の核心を置く。
- 作った呼び名（「驚き箱」のような、読む人が知らない名前）や、かかり方が壊れた言い方（「216万円の兄弟」と読める）。
- 途中で主語が変わって絡まる、何を言っているか1回で分からない（「新作1本で…12日間に2,018万円を集めたこともある」）。
- 概要が仕組みの言葉で書かれていて、場面が浮かばない（悪い例: 「通信を書き換え、本物の代わりの返事を返す」）。使う人が何をして、何が良くなるのかを書く。
- 概要に、その事例を知るのに要らない事（外部資金、買収、黒字か）が入っている。
本文に調べた側のメモが残っていれば外す（「未確認：…」、出典ごとの「ログインなしで読めた／有料の壁なし／利用規約は未確認」、「読めなかった」「集められなかった」「直した点」「指示を受けた」など）。円の断りは「1ドル＝150円で計算」の形にし、「目安」は使わない。意味の取れない文は、分かる文に直すか外す。
次に本文の各章を読み、声に出して引っかかる文（1文に詰め込みすぎ、内輪の言葉・専門語のまま、何の数字か分からない）と、成功の秘訣に作業や数字の羅列が入っていないか（作業なら「実際にやったこと」へ移す）を見る。

## 直し方の決まり
- 事実・数字・年・出典は足さない。消すのは、同じ数字が2か所にある時の片方だけ。言い換えで数字の値や期間を変えない。
- 「（推測）」「（推定）」の印は外さない。印の付いた文を一覧の1行と概要へ持ち込まない。
- です・ますにしない。外貨の円の概算（約…円）は残し、外貨が出るたびに毎回付ける。
- 良い文はそのまま残す。直すのは見劣りする所だけ。
- 章の見出しと形（「1. **見出し**」と次の行の補足、「- 」の箇条書き、「数字と出典」の番号と URL）は崩さない。「数字と出典」の章は、上のメモを外すこと以外は直さない。「一覧の1行の候補」の章は、一覧の1行と同じ見方で読み、引っかかる候補は直す（候補は3つのまま残す。別の担当が1つを選ぶ）。

## 出力
直した後の事例の文の全体を、markdown だけで返す。前置き・説明・直した箇所の一覧・コードの囲み（```）は付けない。
