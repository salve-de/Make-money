# 事例の画面の文を、事例まるごと1回で書く（scripts/case-write/run.ts の「書く」段が渡す指示）

あなたの仕事は1つ。渡された事例について、事業事例サイトの画面に載せる文を、事例まるごと1回で書くこと。出力はすべて日本語。

材料は、下に渡す「集めた事実」と「出典の本文」だけ。web は見られない。材料に無い事実・数字・出典は作らない。

## 書き方の土台
- 根っこ: 私たちは作る側の目線で書くので、作業の報告（「計算した」）、言い訳（未確認・読めなかった）、保身（「目安」、「推定される（推定）」の二重）が画面に漏れる。画面に出す言葉は1語ずつ「読む人に要るか。要るなら、いちばん短く自然な形か」で決める（末尾の docs/owner/READER_EYE.md）。
- 末尾の「見本」（オーナーが承認した Candy Japan）が合格の形。章立て・文の長さ・書き方を真似る。
- さらに末尾の「オーナーとのやりとりと経緯」を必ず読む。一覧の1行と概要は、そこにある見本と同じくらい良い文にする。決まりに当てはめず、見本を読んで、なぜ良いかを掴んで書く。
- 書く前に、3行のあらすじを頭の中で決める（何者か・いくら稼いだか・何が効いたか）。全部の文をこのあらすじに沿わせる。
- 前提を何も知らない人が1回読んで分かる文にする。説明するのは、その事例だけの言葉だけ。サブスク・クラファン・アプリのような普通の言葉は説明しない。
- 1文に1つのことだけを書く。声に出して読んで引っかかる文は書かない。

## 章ごとの役割
| 章 | 書くこと | 書かないこと |
|---|---|---|
| 一覧の1行（1文） | 前提ゼロの人が「なるほど」となる1文。前半にその事例ならではのきっかけ・出来事、後半にいくら稼ぐか、最後は製品・サービスで締める。末尾の「オーナーとのやりとりと経緯」の見本33件と、直す前と直した後の組を読んでから書く | 推定・推測の数字。料金。専門語。作った呼び名 |
| 概要（2段落まで） | 1段落目は、使う人が何をして何が良くなるのかが場面として浮かぶ説明（仕組みの言葉で書かない）。2段落目は、どう始め、どこで伸び、いくら稼いだか | 外部資金・買収・黒字かなど、その事例を知るのに要らない事。推定・推測 |
| 成功の秘訣（1〜5点） | 着想・目の付け所。「1. **見出し**」の行＋次の行に字下げした補足1〜2文 | 作業・値付けの工夫・数字の羅列 |
| 実際にやったこと | 作業・工夫・集客（「- 」の箇条書き） | ― |
| つまずきと立て直し | 失敗・減った時期と、どうしたか（材料が無ければ章ごと省く） | ― |
| 料金 | 値段の体系と、その変化（「- 」の箇条書き） | ― |
| 時間順の流れ | 「- 年月：出来事」 | ― |
| 数字と出典 | 「1. 何の出典か（そこから取った数字・事実）：URL」。外貨を使ったら最後に「- 1ドル＝150円で計算」（この形のまま） | 調べた側のメモ（下の「画面に出さない物」） |

## 一覧の1行で外しやすい3つ（悪い例と良い例の組。例は架空の事例）
形を当てはめず、なぜ引っかかるかを掴んで、声に出して自然かで決める。
- ✗ 手作業の請求書づくりにうんざりして作られ、月の売上が約300万円に達した、…請求書サービス
  ○ 町工場の請求書づくりにうんざりした経理担当が作り、月の売上が約300万円に達した、…請求書サービス
  （物（サービス）が主語の受け身に「うんざりして」という人の気持ちが付くと、誰がうんざりしたのか分からず不自然。気持ちを書くなら人を主語にする。人を出さないなら「〜をきっかけに」のように出来事を前に出す）
- ✗ 会社を辞めた人が、子どもの寝かしつけの記録から作り、…アプリ
  ○ 元消防士が、夜勤明けに付けていた子どもの寝かしつけの記録から作り、…アプリ
  （事実の中に「元消防士」のような落差・意外さのある言葉があるのに「人が」「ある人が」とぼかすと、1行の一番強い所が消える。主語は事実の中でいちばん意外さのある言葉を探して使う。そういう言葉が無ければ主語ごと消し、出来事から書き出す。ぼかした主語は置かない）
- ✗ 釣り人の道具の悩みを独自の工夫で解き、…の売上を上げた、…釣り具
  ○ 濡れた手でも外せる留め具を付けたルアー箱を作り、…の売上を上げた、…釣り具
  （「悩みを…工夫で解き」のような抽象語で包むと場面が浮かばない。何を、どう変えた・作ったのかを、目に見える物と動きで書く）

## 一覧の1行の数字の選び方（悪い例と良い例の組。例は架空の事例）
- ✗ …1回の募集では梱包代だけで約200万円を集めた、…ボードゲーム
  ○ …新作3本の募集で約1,200万円を集めた、…ボードゲーム
  （梱包代だけ・送料だけ・一部の商品だけのような部分の数字は、何の数字か分からず、稼ぎの大きさも伝わらない。1行の数字は、その事例でいちばん大きく、読む人に稼ぎの規模が伝わる、確かめた数字を使う。累計、最も多い年、直近の月など）
- ✗ …広告なしで年2,000万円超を売り上げる、…地図サービス（売上が一番多かったのは数年前）
  ○ …最も多い年には約2,600万円を売り上げた、…地図サービス
  （過去の数字を「売り上げる」「稼ぐ」と現在形にすると、今の稼ぎのように読めて事実がずれる。過去の数字は過去として書く。今も続く数字（直近の月の売上など）だけを現在形にする）
- ✗ 会社を畳んで南米とアフリカを半年回った元銀行員が、ペソ・ランド・ドルの両替記録から作った、…アプリ
  ○ 会社を畳んで旅に出た元銀行員が、旅先の両替記録から作った、…アプリ
  （1行に入れるきっかけは核の1つだけ。行き先や通貨の名前のような細部は、概要に回す。息が続かない長さにしない）

## 事実の決まり（ここだけは機械が照らす）
- です・ますは使わない。常体（〜した、〜だ、体言止め）。
- 外貨には、出てくるたびに毎回、すぐ後ろに円の概算を付ける。1ドル＝150円。「16万ドル（約2,400万円）」の形。前に出た額でも省かない（省くと機械の照合で差し戻される）。同じ数字を何度も書かないようにして、円の重複を減らす。
- 本文の数字と年は、すべて出典の本文か集めた事実にある物だけ。足し算などの計算や、出典に無い見立ては、その文の最後に「（推測）」を付ける（空欄より、印を付けた推測で埋める方がよい）。一覧の1行と概要には推測・推定を入れない。
- 本文（概要か時間順の流れ）には、1行に使う代表の稼ぎの数字（いちばん大きく規模が伝わる、確かめた数字）を必ず入れる。本文に無い数字は1行に使えない。
- 売上と利益を取り違えない。原文が made・revenue・sales なら売上、profit なら利益。どの期間の・何の合計かを書く。
- 「数字と出典」の URL は、渡した出典の URL をそのまま使う。本文を取れなかった出典は使わない。
- 同じ数字は1か所にだけ書く。出典の文章は写さず、自分の言葉で書く。
- 誰かがやった手口を記録するのはよいが、読む人に「こうやれ」と指示する文は書かない。

## 画面に出さない物（オーナーの決定）
本文はすべて読む人の画面に出る。調べた側のメモは本文に書かない。「未確認：…」、出典ごとの「ログインなしで読めた／有料の壁なし／利用規約は未確認」、「読めなかった（本文に使っていない）」「集められなかった」「直した点」「指示を受けた」のような記録は、出力の最後の「## 調べた側のメモ」の章にだけ書く（この章は画面に出ず、別の記録に移される）。円の断りは「1ドル＝150円で計算」の形にし、「目安」は使わない。意味の取れない文は書かない。

## 出力
markdown だけを返す。前置きや説明、コードの囲み（```）は付けない。1行目は「# 事例名」、続けて「## 一覧の1行」「## 概要」「## 成功の秘訣」「## 実際にやったこと」「## つまずきと立て直し」「## 料金」「## 時間順の流れ」「## 数字と出典」の順に章を書き、続けて「## 一覧の1行の候補」（一覧の1行の候補を6つ、「- 」で1行ずつ。前半の3つと後半の3つで、きっかけ・出来事・数字の切り口を変える。候補を出し終えたら、見本33件と「直す前と直した後」の組に並べて、次の2つの問いで1つを選び、それを「## 一覧の1行」の章に入れる。①前提ゼロの人が1回読んで、何の商売で、何が起きて、いくら稼いだかが自然な日本語で分かるか。②見本と並べて見劣りしないか、声に出して引っかからないか。どれも届かなければ、候補を直してから入れる。この1行は後の段で直されないので、ここで決め切る）、最後に「## 調べた側のメモ」（確かめきれなかった数字、読めなかった出典、出典ごとの読めたか・有料の壁・規約の確認など。無ければ「なし」）を付ける。
